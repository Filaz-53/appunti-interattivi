Heap e code con priorità

Un albero quasi completo salvato in un array, che tiene sempre il massimo (o il minimo) in cima. Serve a ordinare in loco in O(n log n) con HeapSort e a implementare le code con priorità usate da Dijkstra, Prim e Huffman.

§1 · La struttura

Heap binari

Alberi completi e quasi completi

Un albero binario completo ha tutte le foglie alla stessa profondità h e ogni nodo interno con due figli: N = 2h+1 − 1 nodi, h ≈ log N. Un albero quasi completo è completo fino al livello h − 1, e i nodi del livello h sono compattati a sinistra.

Max-heap e min-heap

Un albero binario quasi completo è un max-heap se ogni nodo ha un valore ≥ di quello dei figli: A[Parent(i)] ≥ A[i]. È un min-heap se vale ≤. In un max-heap la radice è il massimo.

La forma quasi completa permette di salvare lo heap in un array senza puntatori: A[1] è la radice (A[0] non si usa), e

Parent(i) = ⌊i/2⌋ Left(i) = 2i Right(i) = 2i + 1

L'array ha una lunghezza A.length e lo heap ne occupa i primi A.heapsize elementi. Gli elementi compaiono nell'array nell'ordine della visita in ampiezza (livello per livello, da sinistra).

§2 · Le operazioni

fixHeap, heapify e deleteMax

  • findMax: il massimo è la radice A[1], Θ(1).
  • fixHeap(i): se i sottoalberi dei figli di i sono max-heap ma A[i] è troppo piccolo, lo si scambia con il figlio maggiore e si ripete più in basso. Al più tanti scambi quanta è la profondità: O(log n).
  • heapify: costruisce uno heap da un array qualsiasi. Si rendono heap i due sottoalberi, ricorsivamente, poi si applica fixHeap alla radice.
  • deleteMax: si mette nella radice l'ultimo elemento dello heap e si applica fixHeap: O(log n).

// Lo heap sta in S[1..c]; S[0] non è usato
private static void fixHeap(Comparable S[], int c, int i) {
    int max = 2 * i;                                  // figlio sinistro
    if (2 * i > c) return;                            // i è una foglia
    if (2 * i + 1 <= c && S[2 * i].compareTo(S[2 * i + 1]) < 0)
        max = 2 * i + 1;                              // figlio destro
    if (S[i].compareTo(S[max]) < 0) {
        Comparable temp = S[max]; S[max] = S[i]; S[i] = temp;
        fixHeap(S, c, max);
    }
}

private static void heapify(Comparable S[], int n, int i) {
    if (i > n) return;
    heapify(S, n, 2 * i);          // heap radicato in S[2i]
    heapify(S, n, 2 * i + 1);      // heap radicato in S[2i+1]
    fixHeap(S, n, i);
}
// per trasformare S in uno heap: heapify(S, S.length - 1, 1)
heapify costa O(n), non O(n log n)

T(n) = 2T(n/2) + O(log n) ≤ 2T(n/2) + √n (per n > 16)

Con il Master Theorem: α = log₂ 2 = 1 > β = ½, quindi T(n) = O(n). L'intuizione: la maggior parte dei nodi sta in basso, dove fixHeap fa pochi passi.

§3 · Ordinare con uno heap

HeapSort

  1. Si costruisce un max-heap sull'array con heapify: O(n).
  2. Si prende il massimo (findMax) e lo si toglie con deleteMax: lo heap si accorcia di uno.
  3. Il massimo va nell'ultima posizione liberata dell'array.
  4. Si ripete finché lo heap è vuoto.

public static void heapSort(Comparable S[]) {          // elementi in S[1..n]
    heapify(S, S.length - 1, 1);                        // O(n)
    for (int c = S.length - 1; c > 0; c--) {
        Comparable k = findMax(S);                      // O(1)
        deleteMax(S, c);                                // O(log c)
        S[c] = k;
    }
}

Costo: O(n) + Σc O(log c) = O(n log n) in ogni caso. È in loco (la parte ordinata cresce in fondo allo stesso array) e iterativo, ma non è stabile: gli scambi con la radice spostano elementi lontano dai loro uguali.

§4 · Il tipo di dato

Code con priorità

Definizione

Una coda con priorità mantiene il minimo (o il massimo) di un insieme dinamico di elementi con chiavi totalmente ordinate. Operazioni: findMin(), insert(e, k), delete(e), deleteMin(), increaseKey(e, d), decreaseKey(e, d); delete e le modifiche di chiave assumono l'accesso diretto all'elemento.

Esempio dei lucidi: nel routing si processano prima i pacchetti con priorità più alta (VoIP, videoconferenza). Nel corso le code con priorità tornano in heapselect (capitolo 3), nei codici di Huffman (capitolo 9), in Dijkstra e in Prim (capitolo 11). Si implementano con i d-heap; heap binomiali e di Fibonacci sono approfondimenti non trattati.

§5 · Generalizzazione

d-heap

Definizione

Un d-heap è un albero d-ario perfetto almeno fino alla profondità h − 1, con le foglie del livello h accatastate a sinistra, in cui ogni nodo diverso dalla radice ha chiave ≥ di quella del padre (min-heap). Proprietà fondamentale: la radice contiene una chiave minima (per induzione: i sottoalberi dei figli sono d-heap e la radice è ≤ di tutti i figli).

Altezza: l'albero è completo fino al livello h − 1, quindi n > (dh − 1)/(d − 1) e h < logd(n(d − 1) + 1) = O(logd n).

Array (da A[1]): i figli di i sono in posizione (i − 1)d + 2, …, id + 1, il padre è in ⌈(i − 1)/d⌉. Con d = 2 si ritrovano 2i, 2i + 1 e ⌊i/2⌋.

  1. muoviAlto(v)
  2. while v ≠ root(T) and chiave(v) < chiave(padre(v)) do
  3. scambia di posto v e padre(v)
  4. v = padre(v)

Un confronto per livello: O(logd n).

  1. muoviBasso(v)
  2. repeat
  3. if v non ha figli then return
  4. sia u il figlio di v con chiave minima (d confronti)
  5. if chiave(u) < chiave(v) then scambia u e v else return

d confronti per livello: O(d logd n).

  • insert: nuova foglia nell'ultima posizione, poi muoviAlto.
  • delete(e) e deleteMin: al posto di e si copia l'ultima foglia w, si stacca w, poi muoviAlto e muoviBasso: solo uno dei due fa davvero qualcosa.
  • decreaseKey: si diminuisce la chiave e si fa muoviAlto. increaseKey: si aumenta e si fa muoviBasso.

Perché d > 2? insert e decreaseKey diventano più veloci (l'albero è più basso) e le estrazioni più lente. Conviene quando le decreaseKey sono molte più delle deleteMin, come in Dijkstra su grafi densi.
§6 · Ripasso

Verifica ed esercizi

Esercizio 6.1 · simulazione

heapify su [4, 1, 3, 2, 16, 9, 10, 14, 8, 7]

Qual è il max-heap risultante?

Verificalo nel simulatore con heapify: è lo stesso array che si ottiene con la versione dal basso (i da ⌊n/2⌋ a 1).

Soluzione

  1. I nodi con figli sono le posizioni 1..5. fixHeap su 5 (16, figlio 7): niente. Su 4 (2, figli 14 e 8): scambio con 14.

  2. Su 3 (3, figli 9 e 10): scambio con 10. Su 2 (1, figli 14 e 16): scambio con 16, poi 1 scende ancora sotto 7.

  3. Su 1 (4, figli 16 e 10): scambio con 16, poi 4 scende sotto 14, poi sotto 8.

  4. [16, 14, 10, 8, 7, 9, 3, 2, 4, 1].

Esercizio 6.2 · progettazione

I k elementi più grandi di un flusso di n numeri

Si leggono n numeri uno alla volta e si vogliono i k più grandi alla fine, con memoria O(k).

Soluzione

  1. Si tiene un min-heap di al più k elementi: la radice è il più piccolo dei k migliori visti finora.

  2. Per ogni numero x: se lo heap ha meno di k elementi, insert(x); altrimenti, se x > findMin(), si fa deleteMin e insert(x).

  3. Ogni passo costa O(log k): in tutto O(n log k) tempo e O(k) memoria. Con un max-heap di tutti gli n elementi servirebbero O(n) memoria e O(n + k log n) tempo.

Verifica · capitolo 7

6 domande

In un heap binario su array (radice in A[1]), dove sono i figli di A[6]?

Left(6) = 12, Right(6) = 13. A[3] è il padre.

Quanto costa costruire uno heap da un array di n elementi con heapify?

T(n) = 2T(n/2) + O(log n) = O(n). Con n insert successivi invece servirebbe O(n log n).

L'array [9, 7, 8, 3, 7, 8, 1] è un max-heap?

9 ≥ 7, 8; 7 ≥ 3, 7; 8 ≥ 8, 1. I valori uguali sono ammessi (≥).

HeapSort è stabile?

Lo scambio tra radice e ultimo elemento sposta elementi lontano, oltre i loro uguali. È però in loco, a differenza di MergeSort.

In un d-heap, quanto costa deleteMin?

muoviBasso a ogni livello cerca il figlio minimo tra d: d confronti per O(logd n) livelli.

In un 3-heap su array (da A[1]), qual è il padre di A[9]?

⌈(9 − 1)/3⌉ = ⌈2,67⌉ = 3. I figli di A[3] sono A[8], A[9], A[10]: (3 − 1)·3 + 2 = 8 … 3·3 + 1 = 10.
