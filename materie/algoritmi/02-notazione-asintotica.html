Algoritmi e Strutture di Dati · capitolo 2

Notazione asintotica e ricorrenze

Lo strumento con cui si misura ogni algoritmo del corso: si guarda come crescono tempo e memoria al crescere dell'input, ignorando costanti e termini di ordine inferiore. Poi si impara a risolvere le equazioni di ricorrenza degli algoritmi ricorsivi.

§0 · Orientamento

Cosa chiedono all'esame

L'esercizio 1 dello scritto è sempre un'analisi di costo (vedi la mappa degli esami): una funzione mystery1 con cicli che chiama una mystery2 ricorsiva. Serve saper fare tre cose:

  • contare le iterazioni dei cicli (sommatorie notevoli, cicli che dimezzano);
  • scrivere e risolvere l'equazione di ricorrenza della parte ricorsiva (Master Theorem o iterazione);
  • dimostrare con la definizione o con i limiti che f(n) = O(g(n)), Ω o Θ.
§1 · Il punto di partenza

Funzione di costo e comportamento asintotico

Definizione

Dato n ≥ 0, la funzione di costo f(n) ≥ 0 è la quantità di risorse (tempo di calcolo o memoria) richiesta da un algoritmo su un input di dimensione n.

Secondi e megabyte dipendono da macchina e linguaggio. Il comportamento asintotico invece ignora le costanti additive e moltiplicative e i termini di ordine inferiore, e descrive solo quanto velocemente crescono le risorse: così si confrontano algoritmi indipendentemente dall'hardware.

Esempio dei lucidi

fA(n) = 10³ n contro fB(n) = 10⁻³ n²

Da quale n in poi A è più veloce di B?

10³n < 10⁻³n² ⇔ n > 10⁶. Prima di quel punto vince B grazie alla costante, dopo vince sempre A: è questo che dice l'analisi asintotica.

§2 · Le tre notazioni principali

O-grande, Ω-grande e Θ

O-grande · limite superiore

O(g(n)) = { f(n) | ∃ c > 0, n₀ ≥ 0 tali che ∀ n ≥ n₀: f(n) ≤ c·g(n) }

Le funzioni con ordine di crescita minore o uguale a g(n). Per abuso di notazione si scrive f(n) = O(g(n)) invece di f(n) ∈ O(g(n)).

Ω-grande · limite inferiore

Ω(g(n)) = { f(n) | ∃ c > 0, n₀ ≥ 0 tali che ∀ n ≥ n₀: f(n) ≥ c·g(n) }

Θ · stesso ordine

Θ(g(n)) = { f(n) | ∃ c₁, c₂ > 0, n₀ ≥ 0 tali che ∀ n ≥ n₀: c₁·g(n) ≤ f(n) ≤ c₂·g(n) }

Teorema. f(n) = Θ(g(n)) se e solo se f(n) = O(g(n)) e f(n) = Ω(g(n)).

Esempi dei lucidi · dalla definizione

Trovare le costanti

Soluzione

  1. 3n² + 10n = O(n²). Serve c ≥ (3n² + 10n)/n² = 3 + 10/n. Con n₀ = 1 basta c = 13; con n₀ = 10 basta c = 4.

  2. n³ + 2n² = Ω(n²). Serve c ≤ (n³ + 2n²)/n² = n + 2, vero per ogni 0 < c ≤ 2 e n₀ = 0.

  3. n³ + 2n² = Θ(n³). Serve c₁ ≤ 1 + 2/n ≤ c₂: basta c₁ = 1, c₂ = 3, n₀ = 1.

  4. Metodo: si porta tutto nella forma c ≤ f/g (o ≥) e si cerca un valore di c valido da un certo n₀ in poi.

§3 · Strumenti

o-piccolo, ω-piccolo, limiti e proprietà

o-piccolo e ω-piccolo

o(g(n)) = { f(n) | ∀ c > 0 ∃ n₀ ≥ 0: ∀ n ≥ n₀, f(n) < c·g(n) }

ω(g(n)) = { f(n) | ∀ c > 0 ∃ n₀ ≥ 0: ∀ n ≥ n₀, f(n) > c·g(n) }

La differenza con O e Ω è il quantificatore: per qualche costante contro per tutte. Esempi: 2n = o(n²) ma 2n² ≠ o(n²); n²/2 = ω(n) ma n²/2 ≠ ω(n²). Se f = o(g) allora f = O(g), non il contrario.

Confronto con i limiti

Se limn→∞ f(n)/g(n) esiste ed è:

0 ⇒ f = o(g), quindi f = O(g) · ∞ ⇒ f = ω(g), quindi f = Ω(g) · k > 0 ⇒ f = Θ(g)

Analogia con i numeri reali: O è ≤, o è <, Ω è ≥, ω è >, Θ è =. Ma non tutte le funzioni sono confrontabili: n e n1 + sin n non lo sono, perché la seconda oscilla tra 1 e n².
Quando il limite non esiste

(2 + (−1)ⁿ)n² = Θ(n²), ma il limite del rapporto oscilla tra 1 e 3 e non esiste. Il limite è un criterio sufficiente, non necessario: in questi casi si torna alla definizione (c₁ = 1, c₂ = 3).

ProprietàEnunciatoVale per
Transitivitàf = O(g) e g = O(h) ⇒ f = O(h)O, Ω, Θ, o, ω
Riflessivitàf = O(f)O, Ω, Θ (non o, ω)
Simmetriaf = Θ(g) ⇔ g = Θ(f)Θ
Simmetria traspostaf = O(g) ⇔ g = Ω(f); f = o(g) ⇔ g = ω(f)O/Ω, o/ω
Sommaf₁ = O(g₁), f₂ = O(g₂) ⇒ f₁ + f₂ = O(g₁ + g₂)
Prodottof₁ = O(g₁), f₂ = O(g₂) ⇒ f₁ · f₂ = O(g₁ · g₂)
Costantef = O(g), a > 0 ⇒ a·f = O(g)

Notazione nelle equazioni. 2n² + 3n + 1 = 2n² + Θ(n) significa che esiste una f(n) ∈ Θ(n) che rende vera l'uguaglianza. 2n² + Θ(n) = Θ(n²) significa che per ogni f(n) ∈ Θ(n) il membro sinistro è Θ(n²).

§5 · Costo di un algoritmo

Costo, complessità e i tre casi

Definizioni

Un algoritmo A ha costo computazionale O(f(n)) se la quantità di risorse per eseguire A su un qualsiasi input di dimensione n è O(f(n)).

Un problema P ha complessità computazionale O(f(n)) se esiste un algoritmo che risolve P con costo O(f(n)). Le definizioni valgono anche con le altre notazioni.

Caso ottimo: comportamento nelle condizioni migliori. Caso pessimo: nelle condizioni peggiori. Caso medio: media su tutti i possibili input. Progettando algoritmi interessano soprattutto il pessimo e il medio.

  1. min(Array A[1..n]) → int
  2. m = 1
  3. for i = 2, …, n do
  4. if A[i] < A[m] then
  5. m = i
  6. return m

Il ciclo gira sempre n − 1 volte: i tre casi coincidono, e si può dire Θ(n) (non solo O(n)).

  1. search(Array A[1..n], int x) → int
  2. for i = 1, …, n do
  3. if A[i] == x then
  4. return i
  5. return −1

Ottimo O(1) (x è il primo), pessimo Θ(n) (x è l'ultimo o manca). Medio: con probabilità uniforme Pi = 1/n e costo Ti = i,

Σ PiTi = (1/n)·n(n+1)/2 = (n+1)/2 = Θ(n)

Sommatorie notevoli

Σi=1..n i = n(n+1)/2 · Σi=1..n i² = n(n+1)(2n+1)/6 · Σi=0..n xⁱ = (xn+1 − 1)/(x − 1)

Σi=0..∞ xⁱ = 1/(1 − x) per |x| < 1 · Σi=1..n 1/i ≤ ln n + 1 · Σi=1..n log i = log n! = Θ(n log n)

§6 · Sequenze di operazioni

Analisi ammortizzata

Il costo medio è la media del costo di una operazione; il costo ammortizzato è il costo medio di una sequenza di operazioni. Serve quando un'operazione è a volte molto costosa e a volte molto economica: il caso pessimo è troppo pessimista, e il caso medio richiede ipotesi probabilistiche difficili.

  1. increment(Array A[1..k])
  2. i = k
  3. while i ≥ 1 and A[i] == 1 do
  4. A[i] = 0
  5. i = i − 1
  6. if i ≥ 1 then (se i = 0: overflow)
  7. A[i] = 1

Il bit più significativo è A[1]. Un incremento costa O(1) nel caso ottimo (A[k] = 0) e O(k) nel pessimo (tutti 1): n incrementi costano tra Ω(n) e O(nk). Ma la stima O(nk) è larga.

Metodo dell'aggregazione

Si limita il costo totale di n operazioni e si divide per n. A[k] cambia a ogni incremento, A[k−1] ogni 2, A[k−2] ogni 4…

n + n/2 + n/4 + … + n/2k−1 = Σi=0..k−1 n/2ⁱ ≤ n · Σi=0..∞ 1/2ⁱ = 2n

Costo totale O(n), quindi costo ammortizzato O(1) per incremento.

Metodo degli accantonamenti

A ogni operazione si addebita un costo ammortizzato; la differenza con il costo reale si accumula come credito, che paga le operazioni future più care. Il costo ammortizzato è corretto se il credito non è mai negativo. Qui: 2 € per ogni bit portato da 0 a 1, 1 € paga il cambio e 1 € resta sul bit e pagherà il suo ritorno a 0. Ogni 1 ha sempre 1 € di credito; ogni incremento porta a 1 un solo bit: n incrementi costano 2n €, cioè O(1) l'uno.

L'esempio dei lucidi: spese mensili con picchi fino a 2000 €. Aggregazione: 9300 € in un anno, 775 € al mese. Accantonamenti: con un budget di 775 € al mese si fallisce ad aprile, con 800 € il credito resta positivo.
§7 · Algoritmi ricorsivi

Equazioni di ricorrenza

Un'equazione di ricorrenza descrive ogni elemento di una sequenza in funzione dei precedenti: è il modo naturale di scrivere il costo di un algoritmo ricorsivo. Per comodità si sostituiscono le notazioni asintotiche con costanti e si ignorano gli arrotondamenti, che non cambiano il comportamento asintotico:

T(n) = Θ(1) se n = 1; 2T(⌊n/3⌋) + O(n) se n > 1 → T(n) = 1 se n = 1; 2T(n/3) + cn se n > 1

Metodo dell'iterazione

Si sostituisce la parte ricorsiva finché non compare uno schema legato al passo i, poi si trova quando si arriva al caso base.

T(n) = T(n/2) + c = T(n/4) + 2c = T(n/8) + 3c = … = T(n/2ⁱ) + c·i

Il caso base arriva quando n/2ⁱ = 1, cioè i = log₂ n: T(n) = 1 + c log₂ n = Θ(log n).

Metodo della sostituzione

Si ipotizza una soluzione e la si dimostra per induzione. Esempio: T(n) = T(n/2) + n, ipotesi T(n) ≤ cn. Base: T(1) = 1 ≤ c per c ≥ 1. Passo: T(n) ≤ cn/2 + n = (c/2 + 1)n ≤ cn se c ≥ 2. Quindi T(n) = O(n).

Fibonacci con la sostituzione

O(2ⁿ): T(n) ≤ c2n−1 + c2n−2 + 1 = c2n−2·3 + 1 ≤ c2n−2·4 = c2ⁿ. Ω(2n/2): T(n) ≥ c2(n−1)/2 + c2(n−2)/2 ≥ c2(n−2)/2·2 = c2n/2, con 0 < c ≤ 1/√2.

Il limite stretto viene dal teorema T(n) = 2Fn − 1 (per induzione): T(n) = Θ(φⁿ) ≈ Θ(1.62ⁿ). Con la sostituzione φⁿ è difficile da indovinare.

Metodo dell'albero di ricorsione

Ogni nodo è il costo di un sottoproblema. Si somma il costo livello per livello, poi si sommano i livelli. Serve soprattutto a formulare un'ipotesi da validare con la sostituzione.

Esempi dei lucidi

Due alberi di ricorsione

Soluzione

  1. T(n) = 3T(n/4) + cn². Al livello i ci sono 3ⁱ nodi da c(n/4ⁱ)²: costo (3/16)ⁱcn². Si somma fino a i = log₄ n:

    T(n) ≤ cn² Σi≥0 (3/16)ⁱ = cn² / (1 − 3/16) = O(n²)

    E la sola radice costa cn², quindi anche Ω(n²): Θ(n²).

  2. T(n) = T(n/3) + T(2n/3) + cn. Ogni livello costa al più cn. Il cammino più lungo (n → 2n/3 → 4n/9 …) ha log3/2 n livelli, il più corto (n → n/3 → …) ne ha log₃ n.

  3. Quindi cn log₃ n ≤ T(n) ≤ cn log3/2 n, cioè T(n) = Θ(n log n). Il Master Theorem qui non si applica: i sottoproblemi hanno dimensioni diverse.

§8 · Il metodo rapido

Master Theorem

Teorema (versione generale)

Sia T(n) = d se n = 1, T(n) = aT(n/b) + f(n) se n > 1, con a ≥ 1, b > 1, d costante e f(n) funzione di costo. Allora:

1. se f(n) = O(nlogba − ε) per qualche ε > 0, allora T(n) = Θ(nlogba);
2. se f(n) = Θ(nlogba), allora T(n) = Θ(nlogba log n);
3. se f(n) = Ω(nlogba + ε) per qualche ε > 0 e a·f(n/b) ≤ c·f(n) per qualche c < 1 e n grande, allora T(n) = Θ(f(n)).

Teorema (versione semplificata, quella da usare)

Se T(n) = aT(n/b) + c·nβ con a ≥ 1, b > 1, e α = logb a = log a / log b:

α > β ⇒ Θ(nα) α = β ⇒ Θ(nα log n) α < β ⇒ Θ(nβ)

Il perché in una riga: il livello i dell'albero costa (a/bβ)ⁱ · cnβ. Se a/bβ > 1 vincono le foglie, se = 1 tutti i livelli pesano uguale, se < 1 vince la radice.
Quando non si applica

Non vale per sottoproblemi di dimensioni diverse (T(n/3) + T(2n/3)), né per le ricorrenze «per sottrazione» come quella di Fibonacci T(n − 1) + T(n − 2) + 1. Per queste si usa l'iterazione.

La ricerca binaria

  1. search(Array A[1..n], int x, int i, int j) → int
  2. if i > j then
  3. return −1
  4. else
  5. m = ⌊(i + j)/2⌋
  6. if A[m] == x then return m
  7. else if A[m] > x then return search(A, x, i, m − 1)
  8. else return search(A, x, m + 1, j)

Prima chiamata search(A, x, 1, n). Caso ottimo O(1) (x al centro). Caso pessimo: T(n) = T(n/2) + 1, con a = 1, b = 2: α = 0 = β ⇒ Θ(log n).

Ricorrenze per sottrazione

Agli scritti compaiono spesso ricorrenze in cui n cala di una costante. Si risolvono per iterazione, sommando i costi dei livelli:

RicorrenzaIterazioneSoluzione
T(n) = T(n − 1) + cc + c + … (n volte)Θ(n)
T(n) = T(n − 1) + nn + (n−1) + … + 1 = n(n+1)/2Θ(n²)
T(n) = T(n − 1) + log nlog n + log(n−1) + … = log n!Θ(n log n)
T(n) = 2T(n − 1) + cc(1 + 2 + 4 + … + 2n−1)Θ(2ⁿ)

§9 · Allenamento

Esercizi risolti

Vero o falso? · dagli esercizi del corso

6 domande

6n² = Ω(n³)?

lim 6n²/n³ = lim 6/n = 0, quindi 6n² = o(n³): non può essere Ω(n³). Con la definizione: servirebbe c ≤ 6/n per ogni n grande, impossibile.

n² log n = O(n²)?

lim n² log n / n² = lim log n = ∞: n² log n = ω(n²).

3ⁿ = O(2ⁿ)?

lim 3ⁿ/2ⁿ = lim 1.5ⁿ = ∞. La base dell'esponenziale conta, a differenza della base del logaritmo.

2n+100 = O(2ⁿ)?

2n+100 = 2¹⁰⁰ · 2ⁿ: è una costante moltiplicativa, quindi Θ(2ⁿ).

log n² = Θ(log n)?

log n² = 2 log n. Attenzione: log² n = (log n)² invece non è Θ(log n).

(n + 1)n / 2 = Θ(n²)?

Il limite del rapporto con n² vale 1/2 > 0.

Esercizio 9.1 · dimostrazione

log n! = Θ(n log n)

Soluzione

  1. O: n! = n(n−1)…1 ≤ n·n·…·n = nⁿ, quindi log n! ≤ n log n.

  2. Ω: n! ≥ n(n−1)…(n/2) ≥ (n/2)n/2, quindi log n! ≥ (n/2) log(n/2) = Ω(n log n).

  3. Entrambi i limiti valgono: log n! = Θ(n log n). Serve ogni volta che un ciclo su i fa un lavoro log i.

Esercizio 9.2 · tipo esame

Il costo di mystery1

  1. mystery1(int n) → int
  2. tot = 0; x = 0
  3. while n ≥ 1 do
  4. n = ⌊n/2⌋
  5. x = x + 1
  6. tot = tot + mystery2(x)
  7. return tot
  1. mystery2(int n) → int
  2. sia A[1..n] un array
  3. for i = 1, …, n do
  4. A[i] = 0
  5. return A[n]

Quanto costa mystery1(n) in funzione del valore n?

Il while gira log n volte, e alla x-esima iterazione mystery2 costa Θ(x): Σx=1..log n x = Θ(log² n).

Soluzione

  1. mystery2(n) esegue il for n volte: Θ(n).

  2. Il while di mystery1 dimezza n a ogni giro: ⌊log n⌋ + 1 iterazioni. Alla x-esima chiama mystery2(x).

  3. T(n) = Σx=1..log n Θ(x) = Θ(log n · (log n + 1)/2)

  4. T(n) = Θ(log² n). L'argomento passato a mystery2 è x, non n: è il dettaglio su cui si sbaglia.

Esercizio 9.3 · quattro metodi

T(n) = 2T(n/4) + c

Soluzione

  1. Master Theorem: a = 2, b = 4, α = log₄ 2 = 1/2 > β = 0 ⇒ Θ(√n).

  2. Iterazione: T(n) = 2ⁱT(n/4ⁱ) + c Σk=0..i−1 2k. Con i = log₄ n: 2log₄ n = √n, quindi T(n) = √n·d + c(√n − 1).

  3. Albero: il livello i ha 2ⁱ nodi da c; le foglie sono 2log₄ n = √n. Stesso risultato.

  4. Sostituzione (per Ω): ipotesi T(n) ≥ k√n. T(n) = 2T(n/4) + c ≥ 2k√(n/4) + c = k√n + c ≥ k√n, con 0 < k ≤ d.

  5. T(n) = Θ(√n). Con 4T(n/4) + c si ottiene Θ(n), con 8T(n/4) + c si ottiene Θ(n3/2).

Verifica · ricorrenze

4 domande

T(n) = 2T(n/2) + n (MergeSort)?

α = log₂ 2 = 1 = β: caso uguale, Θ(n log n).

T(n) = 7T(n/2) + n² (Strassen)?

α = log₂ 7 ≈ 2.81 > β = 2: dominano le foglie.

T(n) = T(n − 1) + n?

È per sottrazione: il Master Theorem non si applica. Iterando: n + (n−1) + … + 1 = Θ(n²).

T(n) = 3T(n/4) + n²?

α = log₄ 3 ≈ 0.79 < β = 2: domina la radice.
