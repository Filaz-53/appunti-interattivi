Algoritmi e Strutture di Dati · Java

Java per il corso

Il corso non insegna a programmare: usa Java per implementare gli algoritmi e per il progetto. Qui c'è quello che serve, dalle classi ai generics, fino alle Java Collections con i costi delle operazioni messi accanto alle strutture dati che le realizzano.

§1 · Partire

Le basi

Ogni programma Java è fatto di classi, una per file con lo stesso nome (HelloWorld.java). Il compilatore javac produce bytecode (.class) che la Java Virtual Machine esegue con java. Operatori e strutture di controllo hanno la sintassi del C.


public class HelloWorld {
    public static void main(String[] args) {    // invocato al "run" della classe
        System.out.println("Hello World!");
    }
}

Java è fortemente tipizzato: ogni variabile ha un tipo dichiarato. I tipi primitivi hanno dimensione fissa; i tipi classe sono riferimenti a oggetti.

  • Classi wrapper (Integer, Double, …): servono quando occorre un oggetto, per esempio nelle collezioni. La conversione è automatica (autoboxing e unboxing). Gli oggetti si confrontano con equals o compareTo, non con ==, che confronta i riferimenti.
  • Package: le classi si raggruppano in package (cartelle), dichiarati con package nome; e usati con import java.util.Scanner; o import java.util.*;.
  • String: concatenazione con +, length(), substring(…). enum: un tipo con un insieme finito di valori, come enum Seme { CUORI, QUADRI, PICCHE, FIORI }.
  • Array: dimensione fissa, elementi dello stesso tipo: Integer[] a = new Integer[10]; oppure String[] w = {"cane", "gatto"};. La classe java.util.Arrays offre sort, asList e altri metodi statici.
§2 · Programmazione a oggetti

Classi e oggetti

Una classe definisce campi e metodi; un oggetto è una sua istanza, creata con new, che invoca il costruttore (stesso nome della classe, nessun tipo di ritorno; se ne possono definire più con parametri diversi). L'incapsulamento separa la parte pubblica (l'interfaccia) da quella privata (l'implementazione): si può cambiare la seconda senza toccare il codice che usa la prima.

ModificatoreChi vede il membro
publictutte le classi
protectedle sottoclassi e le classi dello stesso package
(nessuno)le classi dello stesso package
privatesolo la classe stessa
 

public class Rettangolo {
    private int l, h;                       // stato privato

    public Rettangolo(int l, int h) {       // costruttore
        this.l = l;
        this.h = h;
    }
    public int getPerimetro() { return (l + h) * 2; }
    public int getArea()      { return l * h; }
}

// uso
Rettangolo r = new Rettangolo(20, 50);
System.out.println("Area: " + r.getArea());
I lucidi mostrano anche Rettangolo2, che salva area e perimetro invece dei lati: stessa interfaccia, implementazione diversa. È l'incapsulamento in pratica.
§3 · Riuso

Ereditarietà e polimorfismo

Con extends una sottoclasse eredita campi e metodi (non privati) della superclasse, ne aggiunge altri e può ridefinirli. super(…) chiama il costruttore del padre e super.metodo(…) la sua versione di un metodo. Java non ha ereditarietà multipla tra classi, e ogni classe discende da Object.

  • Overriding: stesso nome e stessi parametri del metodo del padre, che viene ridefinito. Overloading: stesso nome, parametri diversi, un metodo diverso.
  • Object definisce toString(), equals(Object), hashCode(): di solito si ridefiniscono. Senza toString si stampa qualcosa come persone.Persona@677327b6.
  • Polimorfismo e dynamic binding: una variabile di tipo statico BankAccount può riferire un JointBankAccount, e a run-time viene eseguito il metodo della classe effettiva.

BankAccount fred     = new BankAccount(123, "Fred", 345.50);
BankAccount fredMary = new JointBankAccount(345, "Fred", "Mary", 450.65);  // lecito
for (BankAccount b : new BankAccount[]{fred, fredMary})
    System.out.println(b);   // BankAccount [...] poi JointBankAccount [...]: decide il tipo dinamico
La trappola di equals

public boolean equals(Persona p) non ridefinisce equals(Object o): è un overloading. Le collezioni chiamano equals(Object) e userebbero ancora quello di Object. La firma deve essere esattamente public boolean equals(Object o), e chi ridefinisce equals deve ridefinire anche hashCode in modo coerente (oggetti uguali, hash uguale), altrimenti HashMap e HashSet non funzionano. L'annotazione @Override fa segnalare l'errore al compilatore.

§4 · Contratti

Classi astratte e interfacce

Una classe con almeno un metodo abstract (senza implementazione) è astratta: non si può istanziare, e ogni sottoclasse concreta deve implementare i metodi astratti (per esempio Shape con getArea e getPerimeter, implementati da Rectangle e Circle). Un'interfaccia contiene solo intestazioni di metodi pubblici (e costanti): una classe la implements e deve implementarne tutti i metodi. Un'interfaccia è un tipo: si possono scrivere metodi che accettano qualunque oggetto che la implementa.

Comparable è l'interfaccia che impone un ordine: compareTo(o) restituisce un numero negativo, zero o positivo se l'oggetto precede, è uguale o segue o. È quella che usano Arrays.sort, Collections.sort e le strutture ordinate come TreeMap.


public class Book implements Comparable<Book> {
    private String title;
    private int pubYear;
    // costruttore e getter omessi

    @Override
    public int compareTo(Book other) {               // ordine per anno di pubblicazione
        return Integer.compare(this.pubYear, other.pubYear);
    }
}
Arrays.sort(books);                                  // usa compareTo
Nei lucidi Book implementa il Comparable «grezzo» con compareTo(Object o), un instanceof e un cast. Con i generics (Comparable<Book>) il cast sparisce e gli errori di tipo li trova il compilatore.
§5 · Errori

Eccezioni

Un'eccezione è un oggetto che porta il controllo dal punto dell'errore a un gestore competente. Si lancia con throw, si gestisce con try … catch: se il tipo lanciato è compatibile (uguale o sottoclasse) con quello di una clausola catch, si esegue quel blocco e si continua dopo il try. Senza gestore il programma termina stampando la pila delle chiamate.


Integer[] a = {1, 4, 5, 76};
try {
    System.out.println(a[10]);
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Houston, abbiamo un problema.");
} catch (IllegalArgumentException e) {
    System.out.println(e.getMessage());
}

public class BadException extends Exception {         // eccezione definita da noi
    @Override public String getMessage() { return "This is a really bad exception..."; }
}

Le sottoclassi di Exception (tranne RuntimeException) sono checked: vanno gestite o dichiarate con throws. Le RuntimeException (indici fuori dall'array, NullPointerException, IllegalArgumentException) sono unchecked.

§6 · Tipi parametrici

Generics

Dalla versione 5, classi e metodi possono avere parametri di tipo: Coppia<T> funziona con qualsiasi tipo, scelto da chi la usa. Per convenzione i parametri sono lettere maiuscole, e possono essere più d'uno (CoppiaMista<A, B>).


public class Coppia<T extends Comparable<T>> {     // vincolo: T deve essere confrontabile
    private T primo, secondo;

    public Coppia(T primo, T secondo) { this.primo = primo; this.secondo = secondo; }

    public void inverti() { T tmp = primo; primo = secondo; secondo = tmp; }

    public T minore() {                                  // compareTo esiste di sicuro
        return primo.compareTo(secondo) <= 0 ? primo : secondo;
    }
}

Coppia<Integer> ci = new Coppia<>(12, 30);              // il tipo si può inferire con <>
  • Il vincolo si scrive sempre con extends, anche quando è un'interfaccia: <T extends Comparable<T>>, oppure <T extends Person>. Se non è rispettato, l'errore è in compilazione.
  • Un parametro di tipo non si può usare con new: niente new T() né new T[n].
  • I generics funzionano solo con tipi classe: ArrayList<Integer>, non ArrayList<int>.
§7 · Le strutture dati già pronte

Java Collections

Il Java Collections Framework offre interfacce (List, Queue, Deque, Set, Map), implementazioni e algoritmi (ordinamento, ricerca). Map<K, V> non deriva da Collection ma ne fa parte. Le collezioni sono Iterable: un Iterator con hasNext() e next() le scorre, ed è quello che fa il for-each.


ArrayList<Integer> integers = new ArrayList<>();
integers.add(5); integers.add(10);
int somma = 0;
for (Integer i : integers) somma += i;               // equivale a usare iterator()

Domanda dei lucidi: quanto costa?

Sommare una LinkedList con for (int i = 0; i < l.size(); i++) sum += l.get(i); costa Θ(n²): ogni get(i) scorre la lista dall'inizio (o dalla fine). Con il for-each, o con un ArrayList, costa Θ(n).

Per Dijkstra e Prim in Java: PriorityQueue non ha decreaseKey, quindi si inserisce di nuovo il vertice con la nuova distanza e, quando si estrae, si scartano le copie vecchie (vertice già chiuso). Il costo resta O(m log n).

Vector e Stack esistono per retrocompatibilità (sincronizzati, più lenti): al loro posto si usano ArrayList e ArrayDeque. Nella pagina del progetto SCC ci sono esempi di HashMap, ArrayList e ArrayDeque usati sulla libreria del corso.

§8 · Ripasso

Verifica ed esercizi

Esercizio dei lucidi · collezioni

Che cosa contiene la sequenza alla fine?

Caso 1, su una coda (add in fondo, remove dalla testa): add(5), add(3), remove(), add(2), add(8), remove(), remove(), add(4). Caso 2, su una deque: addFirst(3), addLast(8), addFirst(2), removeLast(), addLast(7), addLast(4), removeFirst(), removeFirst().

Risultato del caso 1?

[5] → [5, 3] → [3] → [3, 2] → [3, 2, 8] → [2, 8] → [8] → [8, 4].

Soluzione

  1. Caso 1: [5], [5, 3], [3], [3, 2], [3, 2, 8], [2, 8], [8], [8, 4].

  2. Caso 2: [3], [3, 8], [2, 3, 8], [2, 3], [2, 3, 7], [2, 3, 7, 4], [3, 7, 4], [7, 4].

  3. Con LinkedList e ArrayDeque il risultato è lo stesso: cambia solo l'implementazione, non il comportamento dell'interfaccia.
