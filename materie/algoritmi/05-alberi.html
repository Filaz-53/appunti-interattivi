Algoritmi e Strutture di Dati · capitolo 5

Alberi, BST e AVL

La prima struttura non lineare: definizioni, le quattro visite e come si rappresentano gli alberi. Poi gli alberi di gioco (MiniMax e AlphaBeta), gli alberi binari di ricerca e gli AVL, che restano bilanciati con le rotazioni e garantiscono O(log n) nel caso pessimo.

§1 · Definizioni

Alberi

Definizione

Un albero è un insieme di nodi e di archi che li connettono in cui esiste un solo percorso tra due nodi qualsiasi. È radicato se un nodo è la radice, ordinato se i figli di ogni nodo hanno un ordine (primo, secondo…). Ricorsivamente: un albero radicato è vuoto, oppure è una radice R con zero o più sottoalberi disgiunti le cui radici sono collegate a R.

Un albero binario è un albero ordinato in cui ogni nodo ha al più due figli, sinistro e destro: un nodo può avere il destro senza il sinistro.

  • Profondità di u: numero di archi del percorso dalla radice a u. Livello: i nodi alla stessa profondità.
  • Altezza dell'albero: la profondità massima (una sola radice ha altezza 0, l'albero vuoto −1).
  • Grado di un nodo: il numero dei suoi figli. Una foglia ha grado 0.
Teorema

Ogni albero non vuoto con n nodi ha esattamente n − 1 archi (per induzione: ogni nodo tranne la radice ha un solo arco verso il padre). Serve per dimostrare che una struttura non è un albero; il contrario non vale: un grafo con n − 1 archi può non essere un albero.

§2 · Visitare tutti i nodi

Visite in profondità e in ampiezza

La visita in profondità (DFS) scende il più possibile prima di passare al nodo successivo dello stesso livello, in tre varianti che differiscono solo nel momento in cui si visita il nodo. La visita in ampiezza (BFS) procede livello per livello con una coda. Tutte costano Θ(n) in ogni caso.

  1. preorder(Tree T)
  2. if T ≠ NIL then
  3. visit(T)
  4. preorder(T.left)
  5. preorder(T.right)

In-ordine: visit tra le due chiamate. Post-ordine: visit dopo le due chiamate.

  1. BFS(Tree T)
  2. sia Q una nuova coda
  3. if T ≠ NIL then enqueue(Q, T)
  4. while Q.size ≠ 0 do
  5. x = dequeue(Q); visit(x)
  6. if x.left ≠ NIL then enqueue(Q, x.left)
  7. if x.right ≠ NIL then enqueue(Q, x.right)
Esempio dei lucidi

Contare i nodi di un albero binario

  1. countnodes(Tree T) → int
  2. if T == NIL then return 0
  3. else return 1 + countnodes(T.left) + countnodes(T.right)
Domande e risposte

  1. Che visita è? Post-ordine: per valutare T servono prima i valori dei figli.

  2. Quanto costa? Θ(n) in ogni caso.

  3. Come renderla O(1)? Si aggiunge a ogni nodo un campo totnodes. Il prezzo: ogni inserimento o cancellazione deve aggiornare il campo di tutti gli antenati, quindi costa O(h) in più.

§3 · In memoria

Rappresentare un albero

  • Binario con puntatori: ogni nodo ha left, right (e spesso parent). Nella libreria è NodoBinPF con padre, sin, des.
  • Non binario con array di k figli: il numero massimo di figli è fisso, e si spreca spazio se molti nodi hanno meno di k figli.
  • Primo figlio – fratello successivo: ogni nodo punta al primo figlio (first) e al fratello successivo (next); i figli sono una lista concatenata semplice. Nella libreria è NodoPFFS.
  1. preorder(Tree T) (primo figlio – fratello)
  2. if T ≠ NIL then
  3. visit(T)
  4. preorder(T.first)
  5. preorder(T.next)
  1. postorder(Tree T) (mista)
  2. if T ≠ NIL then
  3. tmp = T.first
  4. while tmp ≠ NIL do postorder(tmp); tmp = tmp.next
  5. visit(T)
Con la rappresentazione primo figlio – fratello, la versione solo ricorsiva del post-ordine (postorder(first), postorder(next), visit) visita i fratelli prima del padre comune solo dopo tutto il resto: per questo i lucidi danno anche la versione mista, più leggibile.

La visita in-ordine su un albero non binario va specificata (per esempio: i primi k figli, poi il nodo, poi gli altri); pre-ordine, post-ordine e BFS si generalizzano senza problemi.

§4 · Algoritmi di decisione

Alberi di gioco: MiniMax e AlphaBeta

Un game tree rappresenta tutte le partite di un gioco a turni: i nodi sono situazioni di gioco, gli archi le mosse, le foglie gli stati finali (vittoria, sconfitta, patta). L'albero completo dice la mossa migliore in ogni situazione, ma di solito è troppo grande per essere visitato tutto.

MiniMax

Si etichettano le foglie (1 vittoria, 0 patta, −1 sconfitta, dal punto di vista di A) e si propagano verso la radice: nei turni di A (MAX) il nodo prende il massimo dei figli, nei turni di B (MIN) il minimo. È una visita in post-ordine: tempo Θ(n), memoria O(h).

  1. MiniMax(Tree T, bool playerA) → int
  2. if isLeaf(T) then eval = evaluate(T)
  3. else if playerA then (MAX)
  4. eval = −∞; for c ∈ children(T) do eval = max(eval, MiniMax(c, false))
  5. else (MIN)
  6. eval = +∞; for c ∈ children(T) do eval = min(eval, MiniMax(c, true))
  7. return eval

Quanto è grande l'albero? Con al più m mosse per turno e al più n turni (Forza 4: m = 7, n = 42) i nodi sono al più 1 + m + … + mⁿ = O(mⁿ). In un gioco in cui ogni turno occupa uno di n oggetti (il tris: n = 9) le partite sono al più n! e i nodi Σk n!/(n−k)! ≤ e · n! = O(n!).

AlphaBeta pruning

Stessa soluzione di MiniMax visitando meno nodi. Si mantengono α (il punteggio minimo che MAX si è già assicurato) e β (il massimo che MIN si è già assicurato): [α, β] è l'intervallo dei risultati possibili. Se a un certo punto β ≤ α, il resto del sottoalbero non può cambiare la scelta e si taglia.

  1. AlphaBeta(Tree T, bool playerA, int α, int β) → int
  2. if isLeaf(T) then eval = evaluate(T)
  3. else if playerA then
  4. eval = −∞
  5. for c ∈ children(T) do
  6. eval = max(eval, AlphaBeta(c, false, α, β)); α = max(eval, α)
  7. if β ≤ α then break (taglio β)
  8. else
  9. eval = +∞
  10. for c ∈ children(T) do
  11. eval = min(eval, AlphaBeta(c, true, α, β)); β = min(eval, β)
  12. if β ≤ α then break (taglio α)
  13. return eval
Quanto si guadagna

Caso pessimo: si visita tutto, O(mⁿ). Caso ottimo (si valuta sempre per prima la mossa migliore): metà dei livelli si riduce a un solo figlio, O(mn/2) = O(√(mⁿ)); nel gioco a n oggetti O(√(n!)). È uno speed-up quadratico: a parità di calcoli si guarda il doppio più in profondità. Nel caso medio un buon ordinamento euristico delle mosse avvicina il caso ottimo.

Alberi troppo grandi. Si limita la ricerca a una profondità massima e si valutano le configurazioni non finali con una funzione euristica (valori in [−X, X]). La profondità aiuta anche a scegliere: tra due vittorie la più rapida, tra due sconfitte la più lenta.

IterativeDeepening

Con un limite di tempo si esegue AlphaBeta a profondità 0, 1, 2, …: allo scadere del tempo si usa la mossa migliore trovata all'ultima profondità completata. Memoria O(d), lineare nella profondità (una BFS userebbe O(md)). Tempo: la radice è visitata d + 1 volte, i figli d volte…, ma T(m, d) ≤ md Σ i/mi = O(md), lo stesso ordine di una sola visita a profondità d: domina l'ultimo livello.

Molti stati di gioco si raggiungono con sequenze di mosse diverse: riconoscere le configurazioni già valutate (per esempio con una tabella hash) evita di ricalcolarle.
§5 · La ricerca binaria su un albero

Alberi binari di ricerca

Definizione (BST)

Albero binario in cui ogni nodo v ha una chiave v.key (e dei dati), con la proprietà di ordinamento: le chiavi nel sottoalbero sinistro di v sono ≤ v.key, quelle nel destro sono ≥ v.key. La visita in-ordine restituisce le chiavi ordinate.

  1. search(BST T, Key k) → BST
  2. while T ≠ NIL do
  3. if k == T.key then return T
  4. else if k < T.key then T = T.left
  5. else T = T.right
  6. return NIL

min e max: il nodo più a sinistra e quello più a destra, senza confrontare chiavi.

  1. predecessor(BST T) → BST
  2. if T == NIL then return NIL
  3. if T.left ≠ NIL then return max(T.left) (caso 1)
  4. P = T.parent (caso 2)
  5. while P ≠ NIL and T == P.left do T = P; P = P.parent
  6. return P

Caso 2: il primo antenato di cui T sta nel sottoalbero destro. successor è simmetrico.

insert: si scende come nella ricerca fino a un figlio NIL e si aggancia lì il nuovo nodo come foglia. delete ha tre casi:

  1. il nodo è una foglia: si toglie;
  2. ha un solo figlio: il figlio prende il suo posto sotto il padre;
  3. ha due figli: si copia al suo posto la chiave del predecessore (il massimo del sottoalbero sinistro, che non ha figlio destro) e si cancella il predecessore, che ricade nel caso 1 o 2.
Costo

Tutte le operazioni seguono un percorso radice-foglia: O(h) nel caso pessimo, O(1) nell'ottimo. Ma h può essere qualunque cosa tra log n e n:

h + 1 ≤ n ≤ 2h+1 − 1 ⇒ ⌈log₂(n + 1)⌉ − 1 ≤ h ≤ n − 1

Inserendo chiavi già ordinate l'albero diventa una lista (h = n − 1). Con n inserimenti in ordine casuale si dimostra che l'altezza media è O(log n); con inserimenti e cancellazioni mescolati l'analisi è difficile.

Precisazione sui lucidi

I lucidi dicono che «un BST con altezza h ha almeno 2h nodi»: vale per un albero quasi perfettamente bilanciato (completo fino al livello h − 1), non per un BST qualsiasi, che con altezza h può avere anche solo h + 1 nodi (una catena). Il limite inferiore corretto è quello sopra.

§6 · Bilanciamento garantito

Alberi AVL

Definizioni

Fattore di bilanciamento: β(v) = altezza(v.left) − altezza(v.right). Un albero è bilanciato in altezza se |β(v)| ≤ 1 per ogni nodo. Un albero AVL (Adelson-Velsky e Landis, 1962) è un BST bilanciato in altezza, che si ribilancia da solo dopo ogni inserimento e cancellazione: search, insert e delete costano O(log n) nel caso pessimo.

Altezza di un AVL: alberi di Fibonacci

L'AVL più sbilanciato possibile è l'albero di Fibonacci, in cui ogni nodo interno ha |β| = 1. Il numero di nodi con altezza h è nh = nh−1 + nh−2 + 1, e per induzione nh = Fh+3 − 1 (n₀ = 1, n₁ = 2, n₂ = 4, n₃ = 7). Poiché Fh = Θ(φh), nh = Θ(φh) e quindi h = Θ(log n) per ogni AVL con n nodi.

Ogni nodo memorizza l'altezza del suo sottoalbero, per calcolare β in O(1). Dopo un inserimento o una cancellazione si aggiornano le altezze risalendo verso la radice (O(log n)), fermandosi quando un'altezza non cambia.

Altezza del sottoalbero vuoto

Nello pseudocodice update-height dei lucidi un figlio NIL e un figlio foglia valgono entrambi 0, e così un nodo che ha come unico figlio una foglia risulta di altezza 0 invece di 1. La convenzione che funziona sempre è altezza(NIL) = −1, altezza(v) = 1 + max(altezza(v.left), altezza(v.right)), e β(v) calcolato con la stessa convenzione.

Rotazioni

La rotazione semplice ribilancia in O(1) e preserva l'ordine del BST. Rotazione a destra su u con figlio sinistro v: v sale al posto di u, u diventa figlio destro di v, e il vecchio sottoalbero destro di v diventa sinistro di u.

  1. rotateDX(AVL T, AVL u) → AVL
  2. v = u.left; v.parent = u.parent; u.parent = v
  3. u.left = v.right (e se v.right ≠ NIL, v.right.parent = u)
  4. v.right = u
  5. if v.parent == NIL then T = v (nuova radice)
  6. else if v.parent.left == u then v.parent.left = v else v.parent.right = v
  7. return T

Inserimento e cancellazione

insert: inserimento come nel BST (O(log n)), aggiornamento delle altezze risalendo (O(log n)), e al più un nodo critico (|β| = 2): una rotazione semplice o doppia lo sistema e riporta il sottoalbero all'altezza di prima, O(1).

delete: cancellazione come nel BST, poi si risale verso la radice. Possono esserci più nodi critici, tutti sullo stesso cammino: le rotazioni si possono propagare fino alla radice, O(log n) in tutto.


// asdlab.libreria.AlberiRicerca.AlberoAVL
private void ruota(Nodo v) {
    switch (bil(v)) {
        case +2:
            if (bil(alb.sin(v)) > -1) ruotaDes(v);          // SS (0, +1)
            else { ruotaSin(alb.sin(v)); ruotaDes(v); }      // SD (-1)
            break;
        case -2:
            if (bil(alb.des(v)) < +1) ruotaSin(v);          // DD (-1, 0)
            else { ruotaDes(alb.des(v)); ruotaSin(v); }      // DS (+1)
            break;
    }
}

§7 · Allenamento

Esercizi risolti

Le soluzioni sono scritte in forma parentetica: 60(20, 80) è la radice 60 con figli 20 e 80, e · è un figlio vuoto. Puoi rifare ogni esercizio nel simulatore della figura 3.

Esercizio 7.1 · BST

Inserire 60, 80, 20, 25, 92, 21, 99, 90, poi cancellare 92, 25, 99

Soluzione

  1. Dopo gli inserimenti: 60(20(·, 25(21, ·)), 80(·, 92(90, 99))), altezza 3.

  2. delete 92: ha due figli, il predecessore è 90 → 80(·, 90(·, 99)).

  3. delete 25: un solo figlio (21), che sale sotto 20 → 20(·, 21).

  4. delete 99 (foglia): 60(20(·, 21), 80(·, 90)).

Esercizio 7.2 · AVL

Inserire 50, 20, 10, 60, 40, 45

Quale sbilanciamento provoca l'inserimento di 45?

45 finisce a destra di 40, che è il sinistro di 50, che è il destro di 20: β(20) = −2 e β(50) = +1, caso DS.

Soluzione

  1. 50, 20, poi 10: β(50) = +2 e β(20) = +1, caso SS → rotazione DX su 50: 20(10, 50).

  2. 60 e 40 non sbilanciano: 20(10, 50(40, 60)).

  3. 45 va a destra di 40: β(20) = −2, β(50) = +1, caso DS → rotazione DX su 50, poi SX su 20.

  4. 40(20(10, ·), 50(45, 60))

Esercizio 7.3 · AVL

Continuare con insert 85, insert 55, delete 40, delete 45, insert 15

Soluzione

  1. insert 85, 55: nessuna rotazione → 40(20(10, ·), 50(45, 60(55, 85))).

  2. delete 40 (radice, due figli): il predecessore 20 sale in radice e il suo posto passa a 10. Ora β(20) = −2 con β(50) = −1: caso DD → rotazione SX: 50(20(10, 45), 60(55, 85)).

  3. delete 45 (foglia): 50(20(10, ·), 60(55, 85)), ancora bilanciato.

  4. insert 15: va a destra di 10, β(20) = +2 e β(10) = −1, caso SD → 50(15(10, 20), 60(55, 85)).

Esercizio 7.4 · teoria

delete su un BST è commutativa?

Cancellare u e poi v dà sempre lo stesso albero che cancellare v e poi u?

Basta un controesempio, qui sotto.

Soluzione

  1. Albero 3(1(·, 2), 4).

  2. Prima 3 poi 4: 3 ha due figli, sale il predecessore 2 → 2(1, 4); poi via 4 → 2(1, ·).

  3. Prima 4 poi 3: via 4 → 3(1(·, 2), ·); ora 3 ha un solo figlio, che prende il suo posto → 1(·, 2).

  4. Due alberi diversi: non è commutativa.

Esercizio 7.5 · progettazione

Contare le chiavi in [a, b]

Soluzione
    1. count(BST T, int a, int b) → int
    2. if T == NIL then return 0
    3. if T.key < a then return count(T.right, a, b)
    4. if T.key > b then return count(T.left, a, b)
    5. return 1 + count(T.left, a, T.key) + count(T.right, T.key, b)

  2. Si scartano i sottoalberi che stanno tutti fuori dall'intervallo: O(h) se nessuna chiave è in [a, b], Θ(n) se ci sono tutte.

Esercizio 7.6 · alberi binari

Altezza di un albero binario

Soluzione

  1. In profondità: height(NIL) = −1, height(T) = 1 + max(height(T.left), height(T.right)). Θ(n).

  2. In ampiezza: si accodano coppie [nodo, profondità] partendo da [T, 0]; l'ultimo nodo estratto è il più profondo, e la sua profondità è l'altezza. Θ(n).

  3. Stessa idea per gli altri esercizi su alberi del corso (cancellare le foglie, sommare i valori delle foglie, contare i nodi pari): una visita, Θ(n).

Verifica · capitolo 5

6 domande

Quale visita di un BST restituisce le chiavi in ordine crescente?

Prima il sottoalbero sinistro (chiavi minori), poi il nodo, poi il destro. Invertendo destro e sinistro si ottiene l'ordine decrescente.

Se un nodo di un BST ha due figli, il suo predecessore…

È il massimo del sottoalbero sinistro: se avesse un figlio destro, quello sarebbe più grande. Può però avere un figlio sinistro.

Quanti nodi ha, al minimo, un AVL di altezza 4?

n₄ = F₇ − 1 = 13 − 1 = 12 (oppure n₄ = n₃ + n₂ + 1 = 7 + 4 + 1).

Dopo un inserimento in un AVL, quante rotazioni (semplici o doppie) servono al più?

C'è al più un nodo critico, e la rotazione riporta il sottoalbero all'altezza di prima dell'inserimento. Nella cancellazione invece possono servirne O(log n).

AlphaBeta rispetto a MiniMax…

La potatura elimina solo rami che non possono cambiare la scelta. Il guadagno quadratico c'è solo con l'ordine ottimo delle mosse.

Costo pessimo di search in un BST con n nodi costruito inserendo 1, 2, …, n?

Ogni chiave va a destra della precedente: l'albero è una catena di altezza n − 1. Gli AVL esistono per evitarlo.
