Algoritmi e Strutture di Dati · capitolo 4

Strutture dati elementari

Come si organizzano i dati in memoria e quanto costano le operazioni: il dizionario su array e su lista, le liste concatenate, le pile su array che crescono e si restringono (con l'analisi ammortizzata) e le code su array circolare.

§1 · Definizioni

Strutture dati, prototipo e implementazione

Definizione

Una struttura dati definisce come i dati sono organizzati logicamente e quali operazioni permettono di accedervi e modificarli. Descrive come sono organizzati i dati, non quali dati contiene: una lista può contenere interi o stringhe.

Il prototipo (l'interfaccia) descrive valori e operazioni e nasconde i dettagli: serve a chi usa la struttura. L'implementazione la realizza in un linguaggio, non è visibile all'utente e può cambiare di molto i tempi di esecuzione.

Classificazione
Ordinelineari: elementi in sequenza (primo, secondo…)non lineari: nessun ordine sequenziale (alberi, grafi)
Dimensionestatiche: numero di elementi costantedinamiche: il numero può variare
Tipiomogenee: un solo tipo di datoeterogenee: tipi diversi
§2 · Un prototipo, due implementazioni

Il dizionario

Dizionario (array associativo)

Insieme dinamico di coppie (chiave, valore) con chiavi uniche (i valori possono ripetersi). Operazioni: search(k), insert(k, d), delete(k).


// asdlab.libreria.StruttureElem.Dizionario
public interface Dizionario {
    public void insert(Object e, Comparable k);   // aggiunge la coppia (e, k)
    public void delete(Comparable k);             // rimuove l'elemento con chiave k
    public Object search(Comparable k);           // restituisce l'elemento con chiave k
}

Su array ordinato

search: ricerca binaria, O(log n).
insert: ricerca binaria della posizione O(log n), spostamento in avanti delle coppie con chiave maggiore O(n), scrittura O(1): O(n).
delete: ricerca O(log n) e spostamento indietro O(n): O(n). La coppia si sovrascrive, non serve cancellare l'ultima cella.

Su lista concatenata non ordinata

search: ricerca sequenziale dalla testa, O(n).
insert: in testa alla lista, O(1).
delete: ricerca O(n) e rimozione del nodo O(1): O(n).

«Perché non teniamo la lista ordinata?» Perché la ricerca resterebbe O(n): su una lista non si può fare la ricerca binaria, non c'è accesso diretto all'elemento centrale. Si perderebbe solo l'inserimento in O(1).
§3 · Strutture collegate

Liste concatenate

Una lista organizza gli elementi in ordine sequenziale. Su array l'ordine è dato dagli indici (spazio allocato staticamente, accesso veloce); con le liste concatenate è dato da una catena di puntatori (spazio allocato su richiesta, accesso lento, dimensione illimitata).

  • Semplice (singly linked): ogni nodo x ha x.key e x.next; se x.next = NIL, x è l'ultimo. Si visita in una sola direzione.
  • Doppiamente concatenata: ogni nodo ha anche x.prev; se x.prev = NIL, x è il primo. Si visita nei due sensi.
  • Circolare: doppiamente concatenata in cui next dell'ultimo punta al primo e prev del primo punta all'ultimo. Dalla testa si arriva alla coda in O(1).
  1. insert(List L, Int x) → List
  2. p = new List(x)
  3. p.next = p.prev = p (punta a sé)
  4. if L ≠ NIL then
  5. p.next = L
  6. p.prev = L.prev
  7. L.prev.next = p
  8. L.prev = p
  9. return p (nuova testa)

Inserimento in testa: O(1) in ogni caso.

  1. delete(List L, Int x) → List
  2. p = search(L, x)
  3. if p ≠ NIL then
  4. p.prev.next = p.next
  5. p.next.prev = p.prev
  6. if p == L then (si toglie la testa)
  7. if L.next == L then L = NIL else L = p.next
  8. free(p)
  9. return L

La ricerca costa O(n), gli aggiornamenti O(1): pessimo O(n), ottimo O(1).

  1. search(List L, Int x) → List
  2. if L ≠ NIL then
  3. p = L
  4. repeat
  5. if p.key == x then return p
  6. p = p.next
  7. until p == L
  8. return NIL
Attenzione al «≠»

Nei PDF dei lucidi copiati come testo il simbolo ≠ spesso sparisce e «if L ≠ NIL» diventa «if L = NIL». In tutto lo pseudocodice di inserimento, cancellazione e visita la condizione corretta è diverso da NIL.

Nella libreria del corso, StrutturaCollegata implementa il dizionario con una lista circolare in cui il riferimento list punta all'ultimo nodo: l'inserimento aggiunge dopo list (cioè in testa, che è list.next) e la ricerca parte da list.next.


public void insert(Object e, Comparable k) {
    Record p = new Record(e, k);
    if (list == null) list = p.prev = p.next = p;
    else {
        p.next = list.next;  list.next.prev = p;
        list.next = p;       p.prev = list;
    }
}
§4 · LIFO

Pile (stack)

Una pila supporta push (aggiunge in cima) e pop (toglie l'elemento inserito più di recente): Last In, First Out, come una pila di piatti. Si usa per i record di attivazione delle chiamate, l'undo degli editor, il controllo delle parentesi bilanciate, la DFS iterativa.

  • Con lista semplice: push e pop lavorano sulla testa. Dimensione illimitata, piccolo overhead (un puntatore per elemento). La lista doppia non serve: non si torna mai indietro.
  • Con array: push scrive nella prima cella libera, pop toglie l'ultima. Nessun overhead, ma dimensione limitata: overflow se è piena, underflow se si fa pop da vuota.

In entrambi i casi push e pop costano O(1). Per non avere il limite di dimensione si usa un array dinamico: si raddoppia quando è pieno e si dimezza quando l'occupazione scende a 1/4. Una singola operazione che ridimensiona costa O(n) (la copia), le altre O(1).

Analisi ammortizzata di push (aggregazione)

Partendo da una pila vuota con capacità 1, l'i-esimo push costa ci = i se i − 1 è una potenza di 2 (copia di i − 1 elementi + scrittura), 1 altrimenti:

Σi=1..n ci ≤ n + Σj=0..⌊log n⌋ 2j = n + 2⌊log n⌋+1 − 1 < 3n

n push costano O(n): O(1) ammortizzato. Per i pop si usano gli accantonamenti (2 €: 1 € per la rimozione e 1 € di credito per la copia futura), e si dimostra che ogni sequenza di n push e pop su una pila inizialmente vuota costa O(n).

La strategia conta

Questi costi valgono per «raddoppia a pieno, dimezza a 1/4». Se si dimezzasse quando l'array è pieno per metà, dopo ogni contrazione l'array sarebbe di nuovo pieno: alternando push e pop al confine, ogni operazione copierebbe metà degli elementi, cioè O(n) ammortizzato. Provalo qui sotto.


// asdlab.libreria.StruttureElem.PilaArray
public Object pop() {
    if (this.isEmpty()) throw new EccezioneStrutturaVuota("Pila vuota");
    n = n - 1;
    Object e = S[n];
    if (n > 1 && n == S.length / 4) {           // occupazione a 1/4: dimezza
        Object[] temp = new Object[S.length / 2];
        for (int i = 0; i < n; i++) temp[i] = S[i];
        S = temp;
    }
    return e;
}
§5 · FIFO

Code (queue)

Una coda supporta enqueue (aggiunge in fondo) e dequeue (toglie dalla testa): First In, First Out, come una fila allo sportello. Non si accede agli elementi in mezzo. Si usa nello scheduling dei processi e nella visita in ampiezza (BFS).

  • Lista circolare: enqueue in coda, dequeue in testa. Illimitata, due puntatori per elemento.
  • Lista semplice con un puntatore anche all'ultimo nodo: enqueue in coda in O(1).
  • Array circolare: nessun overhead, dimensione limitata.
  1. enqueue(Queue Q, Int x)
  2. if Q.size == Q.length then error "overflow"
  3. Q.buf[Q.tail] = x
  4. Q.tail = (Q.tail mod Q.length) + 1
  5. Q.size = Q.size + 1
  1. dequeue(Queue Q) → Int
  2. if Q.size == 0 then error "underflow"
  3. x = Q.buf[Q.head]
  4. Q.head = (Q.head mod Q.length) + 1
  5. Q.size = Q.size − 1
  6. return x

tail punta alla prima cella libera, head al primo elemento; il modulo fa ripartire gli indici dall'inizio. Entrambe le operazioni costano O(1). Il campo size serve a distinguere coda piena e coda vuota, che hanno entrambe head = tail.

Domanda dei lucidi: come fare una coda su array circolare dinamico? Quando è piena si alloca un array doppio e si copiano gli elementi a partire da head, nell'ordine della coda (head, head+1, … modulo length), rimettendo head = 1 e tail = size + 1. Copiare l'array così com'è romperebbe l'ordine se la coda «gira» attorno alla fine.
§6 · Allenamento

Esercizi risolti

Esercizio 6.1 · liste

Il k-esimo elemento dalla fine, con una sola visita

Data una lista semplice e un intero k ≥ 1, restituire il k-esimo nodo dalla fine (k = 1 è l'ultimo) senza contare prima la lunghezza.

Soluzione

  1. Due puntatori: tmp1 parte avanti di k nodi, tmp2 dalla testa. Se la lista ha meno di k nodi si restituisce NIL.

    1. lastk(List L, Int k) → List
    2. tmp1 = L; tmp2 = L; i = 0
    3. while tmp1 ≠ NIL and i < k do i++; tmp1 = tmp1.next
    4. if i < k then return NIL
    5. while tmp1 ≠ NIL do tmp1 = tmp1.next; tmp2 = tmp2.next
    6. return tmp2

  3. La distanza tra i due puntatori resta k: quando tmp1 esce dalla lista, tmp2 è sul k-esimo dalla fine. Θ(n), una sola visita.

Esercizio 6.2 · ricorsione su liste

Eliminare gli elementi pari

Con L = [4, 6, 7, 3, 2, 5] il risultato è [7, 3, 5].

Soluzione
    1. deleteEven(List L) → List
    2. if L == NIL then return NIL
    3. if L.key mod 2 == 0 then return deleteEven(L.next) (nodo pari: salta)
    4. L.next = deleteEven(L.next) (nodo dispari: resta)
    5. return L

  2. T(n) = T(n − 1) + 1 = Θ(n). Il trucco è restituire la nuova testa della sottolista e riattaccarla a L.next.

Esercizio 6.3 · analisi di costo

Eliminare i pari e duplicare i dispari

Ogni elemento dispari va replicato tante volte quanti sono i pari che lo precedono: [4, 6, 7, 3, 2, 5] diventa [7, 7, 7, 3, 3, 3, 5, 5, 5, 5]. Qual è il costo nel caso pessimo?

Costo pessimo in funzione di n, la lunghezza della lista?

Con pari e dispari alternati, l'i-esimo dispari ha i pari davanti: Σi=1..n/2 i = Θ(n²) nodi creati.

Soluzione

  1. Si passa nella ricorsione il numero nPrec di pari già visti: un pari incrementa nPrec e viene saltato, un dispari viene ricopiato nPrec volte in testa.

  2. Limite superiore: ogni nodo è duplicato al più tante volte quanti nodi lo precedono, Σi=0..n−1 i = O(n²).

  3. Limite inferiore: con un pari e un dispari alternati il dispari i-esimo ha i pari davanti, Σi=1..n/2 i = (n/2)(n/2 + 1)/2 = Θ(n²).

  4. Il costo pessimo è Θ(n²); il costo ottimo è Θ(n) (solo pari o solo dispari).

Verifica · capitolo 4

5 domande

Un dizionario su array ordinato: quanto costa insert nel caso pessimo?

Trovare la posizione costa O(log n), ma poi bisogna spostare in avanti tutte le coppie con chiave maggiore: O(n).

n push su una pila con array dinamico (raddoppio), partendo da vuota, costano in tutto…

I raddoppi copiano 1 + 2 + 4 + … < 2n elementi: in tutto meno di 3n.

Perché non si dimezza l'array della pila quando è pieno a metà?

Dopo la contrazione l'array è pieno: il push successivo lo raddoppia e il pop dopo lo dimezza di nuovo.

Coda su array circolare di length 8, con head = 7 e size = 3. Quanto vale tail?

Gli elementi occupano le celle 7, 8 e 1; la prima libera è la 2.

Per una pila su lista concatenata conviene la lista…

Push e pop toccano solo la testa: il puntatore prev sarebbe memoria sprecata.
