Algoritmi e Strutture di Dati · capitolo 6

Tabelle hash

Un dizionario con search, insert e delete in O(1) in media: si generalizza l'indicizzazione di un array con una funzione hash. Il prezzo sono le collisioni, che si gestiscono con le liste di trabocco o con l'indirizzamento aperto.

§1 · Il punto di partenza

Tabelle a indirizzamento diretto

Sia U l'universo delle chiavi possibili e K l'insieme delle chiavi usate davvero. Se U = {0, …, m − 1} con m piccolo e |K| ≈ |U|, basta un array T di |U| celle: la chiave k sta in T[k], e search, insert e delete costano O(1). La memoria però è Θ(|U|).

Esempio dei lucidi: identificatori lunghi al più 20 caratteri. |U| > 26 · 3619 ≈ 1031: a 4 byte per cella servirebbero più di 1019 terabyte.
Tabella hash

Quando |K| ≪ |U| si usa un array T[0..m−1] con m = Θ(|K|) e una funzione hash h : U → {0, …, m − 1}. La chiave k va nello slot T[h(k)]. Se due chiavi hanno lo stesso valore hash si ha una collisione: si possono ridurre, non evitare.

Servono quindi tre ingredienti: una funzione hash veloce da calcolare e che distribuisca bene le chiavi, un metodo per gestire le collisioni e una dimensione m adeguata (che di solito si può solo stimare, e che può richiedere di ridimensionare la tabella).

§2 · Distribuire le chiavi

Funzioni hash

Uniformità semplice

Una buona funzione hash distribuisce le chiavi uniformemente: ogni indice i è generato con probabilità 1/m. Per garantirlo bisognerebbe conoscere la distribuzione delle chiavi, cosa di solito irrealistica (con chiavi uniformi in [0, 1), h(k) = ⌊mk⌋ la soddisfa).

Ipotesi di lavoro: tutte le chiavi sono equiprobabili, h si calcola in O(1), e le chiavi sono interi non negativi. Qualsiasi chiave si può trasformare in un intero: con a = 1, …, z = 26 su 6 bit, «beer» diventa 000010 000101 000101 010010, cioè 545.106.

MetodoFormulaPro e contro
Divisioneh(k) = k mod mUna sola divisione. Ma dipende da m: con m = 10 conta solo l'ultima cifra, con m = 2p solo i p bit bassi. Si sceglie m primo, lontano da potenze di 2 e di 10.
Moltiplicazioneh(k) = ⌊m · (kC − ⌊kC⌋)⌋, 0 < C < 1m non è critico; conta la scelta di C. Knuth suggerisce C = (√5 − 1)/2 ≈ 0,618.
Codifica algebricah(k) = (knxⁿ + … + k₁x + k₀) mod mDipende da tutti i bit, cifre o caratteri della chiave. Costosa se calcolata ingenuamente, lineare con la regola di Horner.
Esempi dei lucidi, ricontrollati

Calcolare qualche valore hash

Soluzione

  1. Divisione: m = 12, k = 100 → 100 mod 12 = 4; m = 10, k = 101 → 1.

  2. Moltiplicazione: m = 12, k = 101, C = 0,8 → kC = 80,8, parte frazionaria 0,8, × 12 = 9,6 → 9.

  3. Moltiplicazione con C = (√5 − 1)/2 e m = 1000: per k = 123, kC = 76,018 → 0,018 × 1000 → 18. Per k = 124, come scritto nei lucidi, kC = 76,636 e il risultato è 636: l'esempio dei lucidi ha la chiave sbagliata di un'unità.

  4. Codifica algebrica in base 10: m = 12, k = 234, x = 3 → (2·3² + 3·3 + 4) mod 12 = 31 mod 12 = 7.

Regola di Horner

p(x) = aₙxⁿ + … + a₁x + a₀ = a₀ + x(a₁ + x(a₂ + … + x(aₙ₋₁ + aₙx))): n somme e n prodotti invece di n(n+1)/2 prodotti. Le cifre di una chiave sono poche, quindi il costo si considera costante.


// java.lang.String.hashCode(): codifica algebrica con x = 31, calcolata con Horner
// s[0]*31^(n-1) + s[1]*31^(n-2) + ... + s[n-1], in aritmetica int
public int hashCode() {
    int h = hash;
    if (h == 0 && value.length > 0) {
        for (int i = 0; i < value.length; i++) h = 31 * h + value[i];
        hash = h;
    }
    return h;
}
Paradosso del compleanno: con 23 persone la probabilità che due compiano gli anni lo stesso giorno supera il 50%. Anche con hashing uniforme le collisioni arrivano prestissimo.
§3 · Scansione esterna

Concatenamento

Le chiavi con lo stesso valore hash i stanno in una lista di trabocco, e T[i] punta alla sua testa. search cerca nella lista T[h(k)], insert inserisce in testa, delete toglie dalla lista.

Costi

Sia L la lista più lunga: search e delete costano O(L) nel caso pessimo, O(1) nell'ottimo; insert O(1) sempre. Ma L = O(n): il caso pessimo dipende dal numero di elementi, non da m.

Fattore di carico α = n/m. Con hashing uniforme semplice ogni lista ha in media α elementi, e una ricerca (con o senza successo) costa in media Θ(1 + α): 1 per calcolare h, α (o circa α/2 se la chiave c'è) per scorrere la lista. Se n = O(m), α = O(1) e tutte le operazioni costano O(1) in media.

Il concatenamento non vincola m (né α < 1): m troppo grande spreca spazio, m troppo piccolo allunga le liste.

§4 · Scansione interna

Indirizzamento aperto

Tutte le chiavi stanno nella tabella: ogni slot contiene una chiave o NIL, quindi n ≤ m e α ≤ 1. Se lo slot è occupato se ne ispeziona un altro: la funzione hash prende anche il numero di ispezione, h(k, i), e la sequenza h(k, 0), h(k, 1), …, h(k, m − 1) deve essere una permutazione degli indici, così ogni slot si visita una volta sola.

  1. search(HashTab A, Key k) → Data
  2. i = 0
  3. repeat
  4. j = h(k, i)
  5. if A[j].key == k then return A[j].data
  6. i = i + 1
  7. until A[j] == NIL or i == m
  8. return NIL
  1. insert(HashTab A, Key k, Data d)
  2. i = 0
  3. repeat
  4. j = h(k, i)
  5. if A[j] == NIL or A[j] == DELETED then
  6. A[j] = (k, d); return
  7. i = i + 1
  8. until i == m
  9. error "overflow"
Perché DELETED

Cancellando una chiave non si può rimettere NIL: search si fermerebbe lì e non troverebbe le chiavi inserite dopo, la cui sequenza passava per quello slot. Si scrive DELETED: search e delete lo trattano come pieno (vanno avanti), insert come vuoto (lo riusa).

Nel caso pessimo search, insert e delete costano O(m): si ispeziona tutta la tabella. Il caso medio dipende dalla strategia di ispezione.

§5 · Dove guardare dopo una collisione

Strategie di ispezione

Ispezione lineare

h(k, i) = (h′(k) + i) mod m

Si prova lo slot successivo. Il primo indice determina tutta la sequenza: solo m sequenze distinte. Problema: clustering primario, si formano lunghe sequenze di slot occupati che crescono sempre più (uno slot vuoto preceduto da i slot pieni viene riempito con probabilità (i + 1)/m).

Ispezione quadratica

h(k, i) = (h′(k) + c₁i + c₂i²) mod m

Il passo cresce in modo quadratico. Sempre m sequenze distinte, e c₁, c₂ devono garantire una permutazione. Problema: clustering secondario, due chiavi con la stessa ispezione iniziale hanno la stessa sequenza.

c₁ = 0, c₂ = 1 con m = 10 non è una permutazione

Nell'esempio dei lucidi i² mod 10 vale 0, 1, 4, 9, 6, 5, 6, 9, 4, 1: si raggiungono solo 6 slot diversi su 10, e l'inserimento può fallire anche con la tabella mezza vuota. Con m primo e c₁ = 0, c₂ = 1 si raggiunge almeno metà della tabella; per avere sempre una permutazione si usano per esempio m potenza di 2 con c₁ = c₂ = ½.

Doppio hashing

h(k, i) = (h₁(k) + i · h₂(k)) mod m

Il passo dipende da una seconda funzione hash: è improbabile che due chiavi diverse abbiano sia h₁ sia h₂ uguali, quindi si evitano entrambi i clustering e le sequenze possibili sono più di m. Vincoli: h₂(k) non deve mai valere 0 e deve permettere di visitare tutta la tabella, cioè essere primo con m (per esempio m primo).

§6 · Analisi

Costi medi e fattore di carico

Teoremi (indirizzamento aperto)

Con hashing uniforme semplice, sequenze di ispezione equiprobabili e α = n/m < 1, il numero medio di ispezioni è al più:

ricerca senza successo ≤ 1/(1 − α) ricerca con successo ≤ (1/α) · ln(1/(1 − α))

Se α è costante, O(1). Con la tabella piena al 50%: al più 2 ispezioni senza successo, meno di 2 con successo. Al 90%: al più 10 e meno di 3.

L'ispezione lineare non dà sequenze equiprobabili (per il clustering primario), e i suoi costi medi sono più alti: al più ½(1 + 1/(1 − α)²) senza successo e ½(1 + 1/(1 − α)) con successo.

Le collisioni sono inevitabili anche con poche chiavi, quindi si tiene α basso (α < 0,75 è considerato ottimale) e si ridimensiona la tabella quando supera una soglia. Ridimensionare significa ricostruirla da capo: gli indici hash cambiano con m.

§7 · Allenamento

Esercizi risolti

Gli esercizi del corso si possono rifare nel simulatore. Nella notazione delle soluzioni, · è uno slot NIL e D uno slot DELETED.

Esercizio 7.1 · ispezione lineare

m = 11, h′(k) = k mod 11: inserire 50, 20, 10, 60, 40, 45

In quale slot finisce 45?

45 = 4 · 11 + 1, quindi h′(45) = 1, e lo slot 1 è ancora libero.

Soluzione

  1. 50 mod 11 = 6 → slot 6. 20 mod 11 = 9 → slot 9. 10 mod 11 = 10 → slot 10.

  2. 60 mod 11 = 5 → slot 5. 40 mod 11 = 7 → slot 7.

  3. 45 mod 11 = 1 → slot 1, libero: una sola ispezione.

  4. Tabella (slot 0..10): · 45 · · · 60 50 40 · 20 10. Nessuna collisione in questa sequenza.

Esercizio 7.2 · ispezione lineare

Continuare: insert 85, insert 55, delete 40, delete 45, insert 15

Soluzione

  1. 85 mod 11 = 8 → slot 8 libero. 55 mod 11 = 0 → slot 0 libero: 55 45 · · · 60 50 40 85 20 10.

  2. delete 40 e delete 45: gli slot 7 e 1 diventano DELETED: 55 D · · · 60 50 D 85 20 10.

  3. insert 15: 15 mod 11 = 4 → slot 4 libero.

  4. 55 D · · 15 60 50 D 85 20 10

Esercizio 7.3 · ispezione lineare

Continuare: insert 83, delete 55, insert 90, delete 60

Soluzione

  1. insert 83: 83 mod 11 = 6, occupato da 50; i = 1 → slot 7, che è DELETED: insert lo riusa. 55 D · · 15 60 50 83 85 20 10

  2. delete 55: slot 0 → DELETED.

  3. insert 90: 90 mod 11 = 2 → slot 2 libero.

  4. delete 60 (slot 5): D D 90 · 15 D 50 83 85 20 10

Esercizio 7.4 · concatenamento

m = 10, metodo della moltiplicazione con C = 0,25: inserire 50, 20, 10, 60, 40, 45

Soluzione

  1. h(50) = ⌊10 · frac(12,5)⌋ = 5, h(20) = ⌊10 · frac(5)⌋ = 0, h(10) = ⌊10 · 0,5⌋ = 5, h(60) = 0, h(40) = 0, h(45) = ⌊10 · frac(11,25)⌋ = 2.

  2. Con l'inserimento in testa: T[0] = 40 → 60 → 20, T[2] = 45, T[5] = 10 → 50.

  3. Con C = 0,25 la parte frazionaria vale solo 0; 0,25; 0,5; 0,75: si usano al più 4 slot su 10. È un esempio di cattiva scelta della costante.

Verifica · capitolo 6

6 domande

Con il concatenamento e hashing uniforme semplice, una ricerca costa in media…

1 per calcolare h(k), α per la lista media. 1/(1 − α) è la ricerca senza successo con l'indirizzamento aperto.

Perché nella delete con indirizzamento aperto si scrive DELETED e non NIL?

search si ferma al primo NIL. Una chiave inserita dopo, che era passata per quello slot occupato, risulterebbe assente.

Il clustering secondario riguarda…

Chiavi con lo stesso h′(k) hanno la stessa sequenza quadratica. Il doppio hashing evita entrambi i clustering; la lineare soffre di quello primario.

Perché con il metodo della divisione si evita m = 2p?

k mod 2p sono gli ultimi p bit: chiavi che differiscono solo nei bit alti collidono tutte.

Indirizzamento aperto con sequenze equiprobabili e α = 0,9: quante ispezioni al più, in media, per una ricerca senza successo?

1/(1 − 0,9) = 10.

Doppio hashing con m = 10 e h₂(k) = (k mod 9) + 1: per quale chiave la sequenza non visita tutta la tabella?

h₂ = 2 non è primo con 10: partendo da h₁(1) = 1 si visitano solo gli slot dispari 1, 3, 5, 7, 9. Con 3 (primo con 10) si visitano tutti.
