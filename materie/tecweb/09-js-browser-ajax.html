JavaScript nel browser e Ajax

Come JavaScript modifica la pagina (DOM ed eventi) e come parla con il server senza ricaricarla (Ajax, fetch, Promise). Nel quiz 2026 ci sono state più domande proprio sull'asincronia: callback che non "ritornano", XHR asincrona, chiamate A→B→C, innerHTML.

§1 · DOM

Il DOM

Il DOM (Document Object Model) è la rappresentazione in memoria della pagina come albero di oggetti: ogni elemento, attributo e pezzo di testo è un nodo. Modificando il DOM con JavaScript, la pagina cambia subito. Gli oggetti principali sono window (la finestra), document (la pagina) e navigator (il browser).

Selezionare e modificare

document.getElementById("id") · document.querySelector("css") (il primo che corrisponde al selettore) · document.querySelectorAll("css") (tutti) · getElementsByClassName e getElementsByTagName.
el.textContent = "…" imposta il testo, senza interpretare l'HTML · el.innerHTML = "<p>Ciao</p>" sostituisce tutti i figli di el con i nodi ottenuti interpretando quella stringa · el.classList.add / remove / toggle · el.setAttribute · el.style.color · document.createElement("li") + parent.appendChild(li) · el.remove().

innerHTML (domanda del 2026)

Dopo el.innerHTML = "<p>Ciao</p>" il contenuto precedente di el viene eliminato e al suo posto c'è un nuovo elemento p con il testo "Ciao", non la stringa letterale. Mai inserire con innerHTML testo che arriva dall'utente: potrebbe contenere script (attacco XSS). In quel caso si usa textContent.

§2 · Eventi

Gli eventi


const bottone = document.querySelector("#invia");
bottone.addEventListener("click", (evento) => {
  console.log("cliccato", evento.target);
});
document.querySelector("form").addEventListener("submit", (e) => {
  e.preventDefault();          // blocca l'invio classico e il ricaricamento della pagina
  // … leggo i campi e li mando con fetch
});

Eventi comuni: click, input, change, submit, keydown, mouseover, DOMContentLoaded (il DOM è pronto) e load (la pagina è caricata del tutto). preventDefault() annulla il comportamento predefinito (inviare il form, seguire il link). Gli eventi risalgono l'albero dal figlio ai genitori (bubbling): stopPropagation() li ferma.

Si preferisce addEventListener all'attributo onclick nell'HTML: separa il comportamento dal markup e permette più gestori per lo stesso evento.
§3 · Concetto chiave

Asincronia ed event loop

JavaScript nel browser è single-thread: esegue una cosa alla volta. Le operazioni lente (rete, timer) non bloccano il programma: si avviano, si registra una callback e si prosegue. Quando l'operazione finisce, l'event loop mette la callback in coda, e la esegue appena il codice in corso è terminato.


console.log("A");
setTimeout(() => console.log("B"), 0);
console.log("C");
// stampa A, C, B: la callback aspetta che il codice corrente finisca
Perché la callback non "ritorna" il valore (domanda del 2026)

Nella funzione che fa la richiesta, il codice arriva al return prima che la risposta arrivi: la callback viene eseguita dopo la fine del flusso principale, quando la funzione chiamante è già terminata. Il dato va usato dentro la callback, oppure si restituisce una Promise.

§4 · Ajax

Ajax e XMLHttpRequest

Ajax (Asynchronous JavaScript And XML) non è un linguaggio ma una tecnica: JavaScript chiede dati al server in background e aggiorna solo una parte della pagina. Oggi i dati sono quasi sempre in JSON.

Pro e contro (dagli appunti del corso)

Pro: più interattività (nessuna pagina bianca in attesa); più velocità (si scambiano solo i dati, e una parte del calcolo va sul client); nessun plugin. Contro: il tasto "indietro" e i segnalibri non funzionano come ci si aspetta (non c'è navigazione); i contenuti dinamici sono più difficili da indicizzare per i motori di ricerca; richiede JavaScript attivo; servono attenzioni per l'accessibilità.


const xhr = new XMLHttpRequest();
xhr.open("GET", "/api/libri/");               // asincrona per default
xhr.onload = () => {
  if (xhr.status === 200) mostra(JSON.parse(xhr.responseText));
};
xhr.onerror = () => console.log("errore di rete");
xhr.send();
// il browser resta interattivo mentre aspetta: è l'effetto principale di una XHR asincrona

Lo stato si segue con readyState, da 0 a 4, dove 4 vuol dire completata. Una XHR sincrona (open(…, false)) bloccherebbe tutta la pagina: è deprecata.

§5 · Il modo moderno

Promise, fetch e async/await

Promise

Una Promise rappresenta un valore che arriverà. Può essere pending (in attesa), fulfilled (riuscita) o rejected (fallita). Con .then(f) si usa il risultato, con .catch(g) si gestisce l'errore, con .finally(h) si esegue codice in ogni caso. Ogni .then restituisce una nuova Promise, quindi si possono concatenare, ed un solo catch in fondo raccoglie l'errore di qualunque passaggio precedente.


// fetch restituisce una Promise della risposta HTTP
fetch("/api/studenti/123")
  .then(r => { if (!r.ok) throw new Error(r.status); return r.json(); }) // anche json() è una Promise
  .then(studente => fetch(`/api/studenti/${studente.id}/esami/`))       // B dipende da A
  .then(r => r.json())
  .then(esami => mostra(esami))                                         // C
  .catch(err => console.log("errore:", err));                           // un solo catch per tutti

// la stessa cosa con async/await: si legge come codice sequenziale
async function caricaEsami(id) {
  try {
    const studente = await (await fetch(`/api/studenti/${id}`)).json();
    const esami = await (await fetch(`/api/studenti/${studente.id}/esami/`)).json();
    mostra(esami);
  } catch (err) { console.log("errore:", err); }
}

// POST con JSON
fetch("/api/esami/", { method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ corso: "TW", voto: 30 }) });
Trappole

1. fetch non va in catch per un 404 o un 500: la Promise si rifiuta solo per errori di rete. Bisogna controllare response.ok o response.status. 2. await si usa solo dentro funzioni async (o nei moduli). 3. Per chiamate indipendenti da fare in parallelo si usa Promise.all([…]); per quelle dipendenti (A→B→C) serve la catena o await in sequenza. 4. Le callback annidate una dentro l'altra (il "callback hell") sono la vecchia soluzione: funzionano ma sono difficili da leggere.

Verifica · §3–§5

5 domande

Cosa stampa: console.log(1); setTimeout(()=>console.log(2),0); console.log(3);

Anche con 0 ms la callback va in coda e viene eseguita dopo che il codice corrente è finito.

Una catena p.then(a).then(b).catch(c): se a lancia un errore, cosa succede?

L'errore "scivola" lungo la catena fino al primo catch.

Una fetch riceve una risposta 404. Cosa succede alla Promise?

Per fetch un 404 è una risposta HTTP valida. Solo un errore di rete (server irraggiungibile, CORS) fa rifiutare la Promise.

Devi caricare 3 elenchi indipendenti e mostrarli quando sono arrivati tutti. Cosa usi?

Promise.all le esegue in parallelo e si risolve quando sono finite tutte. Gli await in sequenza funzionerebbero ma sarebbero più lenti.

Dopo el.innerHTML = "<b>Ciao</b>", cosa contiene el?

innerHTML interpreta la stringa come HTML e sostituisce il contenuto. Con textContent comparirebbe il testo letterale.

§6 · Sicurezza

Same-origin policy e CORS

Le regole

Origine = schema + host + porta (https://a.it:443). Per la same-origin policy uno script può leggere le risposte solo da richieste verso la stessa origine della pagina. Per chiamare un'API su un'altra origine serve il CORS (Cross-Origin Resource Sharing): è il server dell'API che deve autorizzarla con l'header Access-Control-Allow-Origin. Per le richieste "non semplici" (metodi come PUT o DELETE, header personalizzati, JSON) il browser manda prima una richiesta OPTIONS di verifica (preflight).
