Server side: Node.js e MongoDB

Cosa succede dall'altra parte: un server Node.js con Express che risponde alle richieste REST e salva i dati in MongoDB. Allo scritto 2026 sono uscite la callback error-first, i protocolli di Node e il campo _id; negli scritti 2024–25 c'era sempre uno schema Mongoose da scrivere. Ed è la base del progetto.

Prima di iniziare · cosa ti serve

JavaScript (oggetti, funzioni, callback), le Promise, REST (le route che scriverai qui) e JSON. Le slide del prof sul server side non sono ancora uscite: da ricontrollare.

§0 · Orientamento

Cosa chiedono all'esame

  • Node.js: event loop single-thread e I/O non bloccante; può implementare anche protocolli diversi da HTTP.

§1 · Panorama

Server side: le opzioni

Lato server un programma riceve le richieste HTTP, esegue la logica dell'applicazione, legge e scrive i dati, e risponde con HTML o JSON. Il programma del corso cita PHP (lo storico, nello stack LAMP: ogni richiesta esegue uno script), Python (Flask, Django) e Node.js (JavaScript, nello stack MEAN/MERN). Nel progetto si usa di solito Node + Express + MongoDB.

§2 · Node

Node.js

Cos'è

Un ambiente che esegue JavaScript fuori dal browser, con il motore V8 di Chrome (2009). Ha un unico thread con un event loop e I/O non bloccante: mentre aspetta il disco, il database o la rete non resta fermo, ma serve altre richieste e riprende con una callback (o una Promise) quando il dato è pronto. Per questo regge molte connessioni contemporanee con poche risorse. Non è adatto a calcoli pesanti per la CPU, che bloccherebbero l'unico thread.

Protocolli: Node non è "un server web": ha moduli per TCP, UDP, HTTP e HTTPS, quindi può implementare anche protocolli diversi da HTTP (domanda del 2026).

npm è il gestore dei pacchetti: npm init crea il package.json (nome, dipendenze, script); npm install express scarica il modulo in node_modules/. I moduli si importano con require("x") (CommonJS) o import x from "x" (ES modules).

La callback error-first

È la convenzione delle API "classiche" di Node: la callback riceve come primo argomento l'errore (null se tutto è andato bene) e poi i risultati. Così l'errore va controllato per primo e non si dimentica.


const fs = require("fs");
fs.readFile("dati.json", "utf8", (err, contenuto) => {
  if (err) { console.error("lettura fallita:", err.message); return; }
  const dati = JSON.parse(contenuto);
  console.log(dati);
});
§3 · Express

Express: route REST in poche righe


const express = require("express");
const app = express();
app.use(express.json());                     // middleware: legge il body JSON in req.body
app.use(express.static("public"));           // file statici (HTML, CSS, JS del client)

app.get("/api/libri/", async (req, res) => {              // collezione
  const libri = await Libro.find({ autore: req.query.autore });   // ?autore=Eco
  res.json(libri);
});
app.get("/api/libri/:id", async (req, res) => {           // individuo: :id è un parametro
  const libro = await Libro.findById(req.params.id);
  if (!libro) return res.status(404).json({ errore: "non trovato" });
  res.json(libro);
});
app.post("/api/libri/", async (req, res) => {
  const nuovo = await Libro.create(req.body);
  res.status(201).location(`/api/libri/${nuovo._id}`).json(nuovo);
});
app.delete("/api/libri/:id", async (req, res) => {
  await Libro.findByIdAndDelete(req.params.id);
  res.status(204).end();
});
app.listen(8000);

req.params sono i pezzi variabili del path (:id), req.query la query string, req.body il corpo (letto dal middleware). Un middleware è una funzione (req, res, next) che passa da tutte le richieste: logging, parsing, autenticazione.

§4 · Dati

MongoDB

Database a documenti (NoSQL)

Invece di tabelle con righe e colonne fisse, MongoDB salva documenti simili a JSON (in formato binario BSON), raccolti in collezioni. I documenti di una collezione possono avere campi diversi e contenere oggetti e array annidati. Il paragone: database ↔ database, tabella ↔ collezione, riga ↔ documento, colonna ↔ campo.

_id: ogni documento ha un campo _id, la chiave primaria, unica nella collezione. Se non lo fornisci, MongoDB genera in automatico un ObjectId (12 byte che contengono anche il momento di creazione). Serve per identificare il documento, e quindi la risorsa REST: /api/libri/<_id>.

Operazioni: insertOne/insertMany, find(filtro) (es. { anno: { $gt: 2000 } }), updateOne(filtro, { $set: {...} }), deleteOne(filtro).

§5 · Esercizio d'esame

Mongoose e gli schemi

Mongoose è una libreria Node che aggiunge a MongoDB gli schemi: per ogni campo si dichiarano il tipo, l'obbligatorietà, i valori ammessi e i default. Dallo schema si crea un model, con cui si fanno le query.

Tipi e opzioni

Tipi: String, Number, Date, Boolean, Buffer, ObjectId, Array, Mixed. Opzioni: required, default, enum: [...], min/max, minlength/maxlength, match (regex), unique. Per un riferimento a un documento di un'altra collezione: { type: Schema.Types.ObjectId, ref: "Persona" }. Le liste si scrivono [String] o [sottoSchema].

Scritto 16/07/2024 · Mongoose

Lo smartphone «TechMaster X100»

"Il 20 luglio verrà lanciato il nuovo smartphone 'TechMaster X100' di Innovatech: display da 6.5 pollici, batteria da 5000 mAh, disponibile nei colori nero, argento e blu. Prezzo di lancio 799 euro, acquistabile online e nei negozi autorizzati. Ogni acquisto include una garanzia di 2 anni e il supporto clienti 24/7." Scrivi lo schema (circa 10 informazioni).

Una soluzione

  1. Si individuano le informazioni: nome, produttore, data di lancio, display, batteria, colori, prezzo e valuta, canali di vendita, garanzia, supporto.

  2. Si scelgono tipi e vincoli: i colori e i canali sono liste con valori ammessi; le misure sono Number con l'unità nel nome del campo; il prezzo ha una valuta.

  3. 
const mongoose = require("mongoose");
const Schema = mongoose.Schema;

const smartphoneSchema = new Schema({
  nome:         { type: String, required: true },          // "TechMaster X100"
  produttore:   { type: String, required: true },          // "Innovatech"
  dataLancio:   { type: Date,   required: true },          // 20 luglio
  displayPollici: { type: Number, min: 0 },                // 6.5
  batteriaMah:  { type: Number, min: 0 },                  // 5000
  colori:       [{ type: String, enum: ["nero", "argento", "blu"] }],
  prezzo: {
    valore: { type: Number, required: true, min: 0 },      // 799
    valuta: { type: String, default: "EUR" }
  },
  canaliVendita: [{ type: String, enum: ["online", "negozi autorizzati"] }],
  garanziaAnni: { type: Number, default: 2 },
  supportoClienti: { type: String, default: "24/7" }
});

module.exports = mongoose.model("Smartphone", smartphoneSchema);

  4. Se nel testo ci sono più entità (un evento e un relatore, per esempio), si scrivono più schemi collegati da un campo ObjectId con ref, oppure si annida un sotto-oggetto

Verifica · capitolo 10

5 domande

Nella convenzione error-first, come è fatta la callback?

Il primo controllo da fare è sempre if (err).

Quali protocolli può gestire Node.js?

Node è un ambiente di esecuzione generico: un server HTTP è solo uno dei programmi che si possono scrivere.

Perché Node.js regge molte connessioni pur avendo un solo thread?

Il modello "un thread per richiesta" è quello di altri server. Node invece aspetta in modo asincrono.

In MongoDB, cosa succede se inserisci un documento senza _id?

_id è obbligatorio e unico: se manca, lo crea il database.

In Express, nella route /api/corsi/:id con richiesta /api/corsi/42?lang=it, dove trovi 42 e "it"?

I parametri del path stanno in params, la query string in query, il corpo della richiesta in body.
