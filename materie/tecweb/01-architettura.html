Architettura del Web

Come è fatto il World Wide Web: chi parla con chi, su quali protocolli, e da dove vengono le tecnologie che usiamo oggi. È la mappa di tutto il corso: ogni concetto qui ha poi un capitolo suo.

Prima di iniziare · cosa ti serve

Niente di particolare. Due parole che ritornano sempre: un protocollo è un insieme di regole condivise su come due programmi si scambiano messaggi; il client è il programma che chiede (il browser), il server è quello che risponde (il programma sul computer che ospita il sito).

§1 · Definizione

Cos'è il World Wide Web

Definizione

Il WWW è un sistema per presentare a schermo documenti multimediali e navigarli con link ipertestuali, distribuito su tutta Internet. Funziona con due ruoli:

Client (browser): visualizza documenti ipertestuali e multimediali e ha un linguaggio di programmazione interno, JavaScript, per controlli sui dati o applicazioni intere.
Server: dà accesso a risorse locali (file, record di database) e le trasmette su TCP, individuate da un identificatore univoco. Può fare da tramite verso applicazioni lato server, così il browser diventa l'interfaccia dell'applicazione.

I tre protocolli fondamentali

URI: lo standard per identificare le risorse di rete e citarle nei documenti (capitolo 3).
HTTP: il protocollo client-server e stateless per accedere alle risorse (capitolo 4).
HTML: il linguaggio per scrivere i documenti ipertestuali, nato da SGML (capitolo 6).

Il web è stato creato nel 1991 da Tim Berners-Lee al CERN di Ginevra per far scambiare documenti ai fisici. Nel 1994 ha fondato il W3C.
§2 · Reti

Le reti a livelli e TCP/IP

Una rete è progettata a livelli: ognuno svolge un compito preciso e si appoggia su quello sotto. Dal basso: il mezzo fisico (onde radio, rame, fibra), il livello fisico, il collegamento (Wi-Fi, Ethernet, 4G/5G), la rete (IP), il trasporto (TCP o UDP) e l'applicazione (HTTP, HTTPS…). Qualunque sia la connessione fisica, dall'alto il web vede sempre IP, TCP e HTTP.

Chi fa cosa

IP: indirizza e instrada i pacchetti (datagrammi). Ogni pacchetto può seguire percorsi diversi, quindi può arrivare in ritardo, fuori ordine o perdersi.
TCP: costruisce sopra IP una connessione affidabile: numera i pacchetti, ritrasmette quelli persi, li rimette in ordine e gestisce le porte (quale applicazione riceve i dati).
UDP: rinuncia alle garanzie per avere meno latenza: va bene per chiamate VoIP, video in diretta, giochi.
DNS: traduce i nomi di dominio (facili da ricordare) negli indirizzi IP (che servono alla rete).

Argomento end-to-end: affidabilità, ordine e sicurezza si verificano agli estremi, negli host che usano davvero i dati. I router intermedi restano "stupidi" e si limitano a instradare pacchetti, mentre l'intelligenza sta agli estremi.

Verifica · §1–§2

3 domande

Quale livello garantisce che i pacchetti arrivino tutti e nell'ordine giusto?

IP consegna "al meglio", senza garanzie. TCP aggiunge numerazione, ritrasmissione e riordino. UDP rinuncia apposta alle garanzie.

Cosa fa il DNS?

www.unibo.it è un nome per esseri umani; la rete ha bisogno dell'indirizzo IP del server.

Quali sono i tre standard su cui si basa il WWW?

URI per identificare le risorse, HTTP per trasferirle, HTML per scrivere i documenti. TCP/IP sta sotto il web, non è "il web".

§3 · Storia

Breve storia (solo quello che serve)

Le tappe

1986 SGML (IBM, standard ISO): il linguaggio di markup dichiarativo da cui nascerà HTML. · 1991 Berners-Lee e Cailliau creano il WWW al CERN. · 1993 Mosaic, il primo browser con immagini, da cui nasce Netscape. · 1994–97 prima guerra dei browser (Netscape contro Microsoft), nascono JavaScript e i linguaggi lato server (Perl, PHP…). 1994 nasce il W3C. · 1996 nasce il CSS: separazione tra struttura e presentazione. · 1997 XML. · 1998 Netscape rilascia il codice, da cui Mozilla e Firefox; nasce Google. · 2004 i produttori di browser fondano il WHATWG: HTML5 diventa un "living standard" (dal 2019 lo gestisce solo il WHATWG). · 2005– Ajax e Web 2.0. · 2007–08 iPhone, Android, Chrome. · 2013– framework a componenti: Angular (Google), React (Facebook), Vue. · 2016– Web Components, ritorno del rendering lato server (Next, Nuxt). · 2023– gli LLM scrivono bene il codice web, e restano centrali le scelte umane su strutture dati, API e astrazioni.

I tre temi trasversali del prof

1. Aperto contro proprietario: TCP/IP, HTML, Linux e Firefox hanno vinto o resistito perché aperti. 2. Dichiarativo contro procedurale: nel dichiarativo dico cosa voglio (HTML, CSS, SQL), nel procedurale come ottenerlo passo per passo (JavaScript). 3. Il web come campo di battaglia costruito sulle macerie delle battaglie precedenti.

§4 · Glossario

Le parole chiave del web moderno

Da sapere definire in una riga

Template e CMS: un template è un documento HTML completo ma vuoto di contenuti, che un motore riempie dal database. Un CMS (WordPress, Drupal) è un motore di template molto sofisticato.
LAMP: Linux, Apache, MySQL, PHP/Perl/Python, la pila open source per i siti dinamici. MEAN/MERN: MongoDB, Express, Angular o React, Node.js.
Architettura a tre livelli: interfaccia utente, logica applicativa, memorizzazione dei dati.
Ajax (Asynchronous JavaScript And XML): la pagina chiede dati al server in background e si aggiorna senza ricaricarsi.
Node.js: esegue JavaScript lato server con il motore V8 di Chrome; con npm ha un ecosistema enorme di moduli.
Responsive design: la pagina si adatta a qualunque schermo. Mobile first: si progetta prima per smartphone.
SPA (Single Page Application): un'unica pagina che carica dati e viste senza cambiare indirizzo.
Framework a componenti: ogni componente racchiude il suo HTML (template), CSS e JavaScript. Opinionated: quanto un framework impone un modello (Angular molto, React poco).
SSR (Server-Side Rendering): l'HTML viene generato sul server; con il CSR lo costruisce il browser. Static site generator: genera in anticipo un sito statico.
PWA (Progressive Web App): un'app web che su mobile si comporta come un'app nativa (offline, notifiche) grazie ai Service Worker.
WebAssembly: codice binario compilato (da C, C++…) che gira nel browser a velocità quasi nativa, accanto a JavaScript.
TypeScript: JavaScript con i tipi, che viene tradotto ("transpilato") in JS. Bundler (Webpack, Vite): impacchettano l'applicazione e le sue dipendenze.

CDN · Content Delivery Network

Una rete di server distribuiti geograficamente che tengono copie di risorse statiche (librerie JS e CSS, immagini, video). Vantaggi: meno latenza, perché risponde il server più vicino; meno carico sul server d'origine; cache condivisa tra siti; resistenza ai picchi e agli attacchi DDoS. Esempi: jsDelivr, cdnjs, unpkg (da cui si includono Bootstrap e Tailwind), Cloudflare, Akamai.

Il prof usa anche il termine «enshittification» (Doctorow): un servizio prima cattura gli utenti, poi i fornitori, poi peggiora la qualità per massimizzare il profitto.
§5 · Oggi

Browser e server oggi

Ogni browser ha un motore di rendering (disegna HTML e CSS) e un interprete JavaScript: Chrome, Edge e Opera usano Blink e V8; Firefox usa Gecko e SpiderMonkey; Safari usa WebKit e Nitro. Su iOS tutti i browser usano WebKit.

Lato server ci sono i server HTTP (Apache, Nginx, IIS, Caddy), gli application server (Node, Deno, Bun, PHP-FPM, Tomcat), i framework e CMS (Laravel, Django, WordPress, Strapi) e il cloud (Docker per impacchettare in container, Kubernetes per orchestrarli, Lambda per eseguire funzioni su richiesta).

§6 · Allenamento

Verifica e ripasso

Verifica · capitolo 1

4 domande

Quale di questi è un linguaggio dichiarativo?

Con il CSS dico cosa voglio ("questo titolo è rosso"), non come disegnarlo. JavaScript, C e Python descrivono i passi.

Cos'è un'applicazione Ajax?

Asynchronous JavaScript And XML. Oggi i dati viaggiano quasi sempre in JSON, ma il nome è rimasto.

Con il Server-Side Rendering…

È il contrario del Client-Side Rendering. SSR dà una prima visualizzazione più veloce e pagine indicizzabili dai motori di ricerca.

Perché il prof cita la nascita del CSS (1996) come una tappa fondamentale?

Prima si usavano "trucchi" presentazionali dentro l'HTML (<font>, tabelle di layout, immagini di testo). Con il CSS l'HTML descrive cosa sono le parti, il CSS come appaiono.
