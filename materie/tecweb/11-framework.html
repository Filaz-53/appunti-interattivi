§1 · Idea

Perché i componenti

Una pagina complessa coordina markup, stile, logica e dati. Nel design a componenti ogni pezzo dell'interfaccia (un pulsante, una scheda prodotto, un menu) è un componente che racchiude il suo template HTML, il suo CSS e il suo JavaScript: è autosufficiente, separato dagli altri e riusabile. La pagina diventa un albero di componenti. L'idea viene da AngularJS (2010) ed è diventata standard con Angular (Google), React (Facebook) e Vue (comunità open source).

Il prof la chiama la "terza guerra dei browser": il campo di battaglia non è più il browser degli utenti ma la testa degli sviluppatori.
§2 · Concetti comuni

Props, stato e reattività

I tre concetti di ogni framework

Props (proprietà): i dati che un componente riceve dal genitore; sono di sola lettura per il figlio.
Stato: i dati che il componente possiede e può cambiare (il testo di un campo, una lista caricata da un'API).
Reattività: quando lo stato cambia, il framework aggiorna da solo la vista. Non si tocca il DOM a mano: si descrive come deve apparire l'interfaccia per un certo stato, cioè in modo dichiarativo.
Flusso dei dati tipico: verso il basso con le props, verso l'alto con gli eventi e le callback.

§3 · React

React

Cosa ha cambiato React (domanda del 2026)

I framework precedenti (AngularJS, Knockout…) estendevano l'HTML con template e direttive, e il DOM veniva aggiornato modificando pezzi dell'interfaccia. React rovescia il punto di vista: l'interfaccia è una funzione dello stato, scritta in JavaScript (con JSX), UI = f(stato). A ogni cambiamento di stato il componente viene "ridisegnato" su un Virtual DOM (una copia leggera del DOM in memoria); React confronta la versione nuova con la vecchia (diffing) e applica al DOM reale solo le differenze. Il flusso dei dati è unidirezionale. È poco "opinionated": è una libreria per la vista, e il resto (routing, gestione dello stato) lo scegli tu.


import { useState, useEffect } from "react";

function ListaEsami({ studenteId }) {                 // studenteId è una prop
  const [esami, setEsami] = useState([]);             // stato
  useEffect(() => {                                   // effetto: carica quando cambia studenteId
    fetch(`/api/studenti/${studenteId}/esami/`).then(r => r.json()).then(setEsami);
  }, [studenteId]);
  return (                                            // JSX: sembra HTML ma è JavaScript
    <ul>
      {esami.map(e => <li key={e.id}>{e.corso}: {e.voto}</li>)}
    </ul>
  );
}

Hook principali: useState (stato), useEffect (effetti collaterali come fetch e timer), useContext, useRef. Nelle liste si usa una key unica per ogni elemento. React Native porta lo stesso modello alle app mobili.

§4 · Gli altri

Vue e Angular

Vue

Open source, nato nel 2014 da un ex sviluppatore di AngularJS. Usa template HTML con direttive: v-if, v-for, v-bind (abbreviato :), v-on (@), v-model (collegamento bidirezionale con i campi dei form). I componenti si scrivono in file .vue con tre blocchi: template, script e style. La reattività è automatica (ref, reactive). È progressivo: lo si può usare anche solo in una parte della pagina.


<template>
  <form @submit.prevent="aggiungi">
    <input v-model="titolo" required> <button>Aggiungi</button>
  </form>
  <ul><li v-for="l in libri" :key="l._id">{{ l.titolo }}</li></ul>
</template>
<script setup>
import { ref, onMounted } from "vue";
const libri = ref([]), titolo = ref("");
onMounted(async () => { libri.value = await (await fetch("/api/libri/")).json(); });
async function aggiungi() {
  const r = await fetch("/api/libri/", { method: "POST",
    headers: { "Content-Type": "application/json" }, body: JSON.stringify({ titolo: titolo.value }) });
  libri.value.push(await r.json()); titolo.value = "";
}
</script>
Angular

Di Google (riscrittura di AngularJS del 2016). È un framework completo e molto "opinionated": impone struttura, TypeScript obbligatorio, moduli, servizi con dependency injection, routing, form e HTTP già inclusi, e una CLI. Template con binding ({{ }}, [prop], (evento), [(ngModel)] bidirezionale). Adatto a grandi progetti aziendali; la curva di apprendimento è più ripida.

Verifica · §1–§4

4 domande

Qual è il principio che distingue React dai framework precedenti basati su template HTML?

Invece di estendere l'HTML con direttive e modificare il DOM a mano, si descrive cosa mostrare per ogni stato e React applica solo le differenze.

Differenza tra props e stato?

I dati scendono con le props; per comunicare verso l'alto il figlio chiama una callback ricevuta come prop o emette un evento.

Cos'è il Virtual DOM?

Il Virtual DOM serve a ridurre gli aggiornamenti costosi del DOM. Lo Shadow DOM invece serve a incapsulare: sono cose diverse.

Quale framework è il più "opinionated" e impone TypeScript?

Angular fornisce e impone tutto (struttura, DI, routing, TypeScript). React è il meno opinionated.

§5 · Standard

Web Components e Shadow DOM

L'idea dei componenti è entrata negli standard del browser: i Web Components permettono di creare nuovi elementi HTML riusabili senza framework. Il prof lo legge come un ritorno al dichiarativo: HTML torna estendibile con elementi propri.

I tre ingredienti

Custom Elements: si definisce un nuovo tag (il nome deve contenere un trattino) con una classe JS: customElements.define("mia-scheda", MiaScheda).
Shadow DOM: un sotto-albero DOM incapsulato attaccato all'elemento. Gli stili e gli script della pagina non entrano, e quelli del componente non escono: è un "mini-DOM protetto" (domanda del 2026). Non serve a nascondere l'elemento né a renderlo più veloce.
<template> e <slot>: markup non visualizzato da clonare, e punti in cui inserire il contenuto passato dall'esterno. Con il Declarative Shadow DOM (2023) lo Shadow DOM si può scrivere anche direttamente in HTML.


class SalutoBox extends HTMLElement {
  constructor() {
    super();
    const ombra = this.attachShadow({ mode: "open" });
    ombra.innerHTML = `<style>p { color: teal }</style><p>Ciao <slot></slot>!</p>`;
  }
}
customElements.define("saluto-box", SalutoBox);
// in HTML: <saluto-box>Arianna</saluto-box> — il p teal non colora gli altri p della pagina
§6 · Rendering

SPA, SSR e CSR

Dove si costruisce la pagina

SPA (Single Page Application): un'unica pagina HTML; la navigazione cambia vista con JavaScript (un router lato client) senza ricaricare.
CSR (Client-Side Rendering): il server manda un HTML quasi vuoto più il JS, e il browser costruisce il DOM. Dopo il caricamento è molto interattiva, ma la prima visualizzazione è lenta e l'indicizzazione più difficile.
SSR (Server-Side Rendering): il server genera l'HTML completo prima di inviarlo; poi il JS nel browser lo "idrata", cioè ci collega gli eventi e lo rende interattivo. La prima visualizzazione è veloce ed è buona per i motori di ricerca. Esempi: Next.js (React), Nuxt (Vue).
Static site generation: l'HTML viene generato una volta sola, al momento della build.
