§1 · Concetti

Risorse e URI

Il web ha tre ingredienti: identificazione (ogni cosa d'interesse è una risorsa con un identificatore globale, l'URI), interazione (HTTP per scambiare messaggi) e formato (HTML, JPEG, PNG… da riconoscere correttamente).

Risorsa

Qualunque cosa sia oggetto di scambio sul web, indipendentemente da come è memorizzata. Può essere un file, ma anche un record di un database (l'URI è la chiave), il risultato di un'elaborazione (l'URI ne contiene i parametri), un oggetto fisico (un libro, una persona) o un concetto astratto. Per questo si dice "risorsa" e non "file".

Gli URI sono probabilmente il motivo del successo del web: una sintassi universale, indipendente dal protocollo, facile da scrivere e scambiare.

§2 · Locator e names

URL e URN

Le due facce degli URI

URL (Locator): contiene le informazioni per accedere subito alla risorsa (protocollo, host, percorso). È comodo ma fragile: se la cartella cambia nome, il link si rompe.
URN o names: un nome stabile e permanente della risorsa, senza informazioni di accesso. Per usarlo serve un servizio che lo traduca nell'URL attuale (da aggiornare a ogni spostamento). Esempio: un codice ISBN di un libro.

Visione moderna: più che la distinzione URL/URN conta lo schema (la parte prima dei due punti). Alcuni schemi sono per natura persistenti, altri contengono informazioni di accesso: dipende dallo schema.

URL permanenti (purl.archive.org, i permalink dei blog): un sistema server-side prende l'URL "virtuale" e restituisce la risorsa (dereferenziazione) oppure risponde con un redirect verso l'URL fisico di oggi.
§3 · Sintassi

La sintassi di un URI

schema : [ // authority ] path [ ? query ] [ # fragment ]

authority = [ userinfo @ ] host [ : port ]

Esempio scomposto

https://mario@www.uni.it:8080/corsi/tw/lez.html?anno=2026&lang=it#esercizi

Le parti

  1. schema = https (registrato presso IANA; negli URL è di fatto il protocollo)

  2. authority = mario@www.uni.it:8080: userinfo mario (sconsigliato, è un rischio di sicurezza), host www.uni.it (nome DNS o indirizzo IP), porta 8080 (si omette se è quella standard: 80 per http, 443 per https)

  3. path = /corsi/tw/lez.html (gerarchico, a livelli separati da /)

  4. query = anno=2026&lang=it (parametri, di solito nella forma nome=valore uniti da &)

  5. fragment = esercizi (una sotto-parte della risorsa; la gestisce il client e il server non lo riceve nemmeno)

Principi di progettazione

Trascrivibili: pochi caratteri, per poterli scrivere anche su carta. · Identificazione, non interazione: l'URI dice cosa, non quale operazione fare (quella la dice HTTP). · Gerarchici: : separa lo schema, / i livelli, ? la query, # il frammento.

Altri schemi: mailto:a@b.it · file:///percorso (file locali, niente HTTP) · data:image/png;base64,iVBOR… (non punta a una risorsa ma la contiene: si usa per piccole immagini inline) · ftp:// (porta 21, ormai non più supportato da molti browser).

§4 · Caratteri

Caratteri ammessi e percent-encoding

Tre categorie

Non riservati: lettere, cifre e - . _ ~, che si usano liberamente.
Riservati: : / ? # [ ] @ e ! $ & ' ( ) * + , ; =. Hanno una funzione di delimitatore: si usano così quando svolgono quella funzione, altrimenti vanno codificati.
Percent-encoded %XX, con XX il byte in esadecimale. Servono per i caratteri non ASCII (si codificano in UTF-8 e poi ogni byte diventa %XX), per i caratteri di controllo, per lo spazio e < > " { } | \ ^ `, e per i riservati usati come testo.

Esempi: lo spazio è %20; "è" (C3 A8 in UTF-8) è %C3%A8.

Trappola

…/uno/due/tre e …/uno/due%2Ftre non sono uguali. Nel primo lo slash separa due livelli; nel secondo %2F è un carattere del nome, e l'ultimo segmento si chiama letteralmente "due/tre".

§5 · L'esercizio tipico

Risolvere un URI relativo

Un URI reference (relativo) riporta solo una parte dell'URI, tagliando da sinistra, e si interpreta rispetto a un URI base (di solito quello della pagina che lo contiene). Risoluzione = ottenere l'URI assoluto. Dereferenziazione = ottenere la risorsa.

L'algoritmo (base = http://www.site.com/dir1/doc1.html)

1. Inizia con #: frammento dello stesso documento. #a1 → http://www.site.com/dir1/doc1.html#a1
2. Inizia con uno schema: è già assoluto.
3. Inizia con //: stesso schema della base, il resto è nuovo. //www.b.com/x.html → http://www.b.com/x.html (https se la base è https).
4. Inizia con /: path assoluto sullo stesso host. /dir3/doc3.html → http://www.site.com/dir3/doc3.html
5. Altrimenti: si prende il path della base togliendo l'ultimo elemento (/dir1/), si aggiunge il relativo e si semplifica: ./ si cancella, ../ si cancella insieme al livello precedente.
doc4.html → http://www.site.com/dir1/doc4.html · ../doc7.html → http://www.site.com/doc7.html

Esempi della prof · base http://www.sito.com/uno/due/tre

Risolvi ciascun riferimento

Soluzioni

  1. pippo e ./pippo → http://www.sito.com/uno/due/pippo (tre è l'ultimo elemento, e viene tolto)

  2. #pluto → http://www.sito.com/uno/due/tre#pluto · pippo#pluto → …/uno/due/pippo#pluto

  3. . e ./ → http://www.sito.com/uno/due/ · .. e ../ → http://www.sito.com/uno/

  4. ../pippo → http://www.sito.com/uno/pippo · ../.. → http://www.sito.com/ · ../../pippo → http://www.sito.com/pippo

  5. pippo:pluto → pippo:pluto (inizia con uno schema, "pippo:", quindi è già assoluto!)

Verifica · risoluzione

4 domande

Base https://example.com/a/b/pagina.html, link ../img/logo.png. Risultato?

Si toglie pagina.html e resta /a/b/; .. sale a /a/; si aggiunge img/logo.png. È la domanda del 12/02/2026.

Base http://www.uni.it/corsi/tw/index.html, link /esami.html. Risultato?

Lo slash iniziale vuol dire path assoluto sullo stesso host: si riparte dalla radice.

Base https://a.it/x/y.html, link //cdn.it/lib.js. Risultato?

Il doppio slash vuol dire nuovo host con lo stesso schema della base (https). Era usato per i link che dovevano funzionare sia in http sia in https.

Quando chiedi http://sito.it/pagina.html#cap3, cosa riceve il server?

Il fragment è gestito dal client: il browser scarica tutta la pagina e poi scorre fino a #cap3.

§6 · Server e approfondimenti

Route, rewriting e sicurezza

Route

Una route associa il path di un URI a una risorsa del server. File-system route (il vecchio approccio di Apache): la radice del path corrisponde a una cartella e ogni file diventa un URI. Managed route (Node.js ed Express): il programmatore associa ogni path a una funzione che restituisce la risorsa, statica o calcolata.


const router = require("express").Router();
router.get("/name",  (req, res) => res.send("<p>Fabio</p>"));     // http://example.com/name
router.get("/email", (req, res) => res.send("fabio.vitali@unibo.it"));
app.use("/css", express.static("css"));   // file statici della cartella css/

URL rewriting (es. mod_rewrite di Apache): espone /Argomento al posto di /wiki/index.php?title=Argomento. Nasconde i dettagli tecnici e rende i nomi duraturi e "semantici". URI template (RFC 6570): schemi con segnaposto, come /users{/id}{?q,lang}, che l'applicazione riempie (sono usati nelle API e nel routing dei framework).

Sicurezza · open redirect

Se un template /{lang}/{username} riceve lang vuoto e username "evil.org", si ottiene //evil.org, cioè un URI che punta a un altro host, e i dati del form finiscono lì. Scrivendo il template come ./{lang}/{username} si ottiene invece una pagina inesistente sullo stesso sito.

§7 · Ripasso

Verifica finale e checklist

Verifica · capitolo 3

3 domande

Qual è la differenza tra URL e URN?

Locator contro names. Entrambi sono URI.

Come si scrive uno spazio dentro un URI?

Lo spazio (0x20) non è ammesso e va percent-encoded. Nella query string dei form si vede spesso anche il + al suo posto.

Cosa fa uno URI con schema data:?

Esempio: data:image/png;base64,iVBOR…: l'immagine sta nell'URI stesso, senza una richiesta HTTP separata.
